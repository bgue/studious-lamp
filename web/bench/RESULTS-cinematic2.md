# Benchmark results: cinematic plugin, second round

Generated by `node bench/bench-cinematic2.mjs` on 2026-10-31.

**Swiftshader numbers are CPU rasterisation, not GPU numbers.** The headless Chromium (WebGL renderer: ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)) draws
the 1920x1080 frame on the CPU, so the frame times below are far above what a laptop GPU would give. Algorithm 1 and 2 timings are
pure JavaScript (three-mesh-bvh on the CPU) and are the meaningful part of this table; they are unaffected by the rasteriser except that
the main thread shares the machine with it.

- Algorithm 1: 10 runs, geometry distance/intersection caches cleared before each (cold), mean / p95 ms
- Algorithm 2: camera orbited through 36 azimuths (elevation fixed), runs triggered by the app's own debounced camera handler (at most one per 50 ms), mean / p95
- Frame interval: requestAnimationFrame deltas during the orbit; frame CPU: JS time of smoothing + `renderer.render()` call (excludes asynchronous GPU/raster work)
- Focus / host / near / far are bucket sizes from Algorithm 1

## Notes added after the run

**Interleaved A/B of the two defaults-on features** (same page, 1920x1080, 5 rounds of 6 s each, new features off then on, with the duct
re-selected every 1.5 s so a sweep is running about two thirds of the time; script was a throwaway, numbers below):

| model | frame CPU ms, sweep + grading off (mean / median) | on (mean / median) | frame interval ms off / on |
| --- | --- | --- | --- |
| building | 0.453 / 0.411 | 0.395 / 0.381 | 148 / 159 |
| synth5k | 1.139 / 1.052 | 1.357 / 1.067 | 349 / 392 |

Means include one outlier round each; medians differ by -7% (building) and +1% (synth5k). Both features are shader-only (the sweep adds a
plane update per frame while it runs), so the JS cost is within noise. In swiftshader the frame interval grows about 7% (building) to 12%
(synth5k) with them on, which is extra rasterisation work in the ghost and opaque fragment shaders. Verdict: both stay on by default.

**`node bench/bench.mjs` with the plugin defaults** (run once, its RESULTS.md output was discarded and the committed one restored): frame CPU
mean synth5k 0.7 / 0.9 ms (500 / 300 samples), building 0.5 / 0.5 ms, against 1.0 / 1.2 / 0.5 / 0.4 in the committed RESULTS.md.

**AO + vignette cost.** The table above shows the AO+vig mode: frame CPU about 1.5 to 2.4x the normal one on synth5k and 1.2 to 2x on the
building, and a frame interval 3 to 6x longer in swiftshader (CPU rasterisation of a multisampled render target, a GTAO pass at half
resolution, its denoise pass and the full-screen copy and vignette). That is a CPU-rasteriser number, not a GPU number. Switching the
pipeline on or off also makes swiftshader recompile every material's shader (the render-target state is part of the program key), which
takes several seconds there and is included in the first frames after a toggle.
