# Benchmark results: cinematic plugin

Generated by `node bench/bench-cinematic.mjs` on 2026-10-31.

**Swiftshader numbers are CPU rasterisation, not GPU numbers.** The headless Chromium (WebGL renderer: ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)) draws
the 1920x1080 frame on the CPU, so the frame times below are far above what a laptop GPU would give. Algorithm 1 and 2 timings are
pure JavaScript (three-mesh-bvh on the CPU) and are the meaningful part of this table; they are unaffected by the rasteriser except that
the main thread shares the machine with it.

- Browser: Chromium 153.0.8010.12, viewport 1920x1080, `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`
- Scene: `/?model=<name>`, first IfcDuctSegment selected programmatically (`app.selectIds([id])`), X-ray on, default settings
- Algorithm 1: 10 runs, geometry distance/intersection caches cleared before each (cold), mean / p95 ms
- Algorithm 2: camera orbited through 36 azimuths (elevation fixed), runs triggered by the app's own debounced camera handler (at most one per 50 ms), mean / p95
- Frame interval: requestAnimationFrame deltas during the orbit; frame CPU: JS time of smoothing + `renderer.render()` call (excludes asynchronous GPU/raster work)
- Focus / host / near / far are bucket sizes from Algorithm 1
