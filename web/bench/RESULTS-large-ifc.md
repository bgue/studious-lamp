# Large IFC load: before and after

Generated by `node bench/bench-large-ifc.mjs --n 20000,100000 [--single] --label <name>` (headless Chromium, swiftshader, the file opened through the hidden file input of the dev app or of `dist-single/xray-viewer.html`). Files come from `tools/make_big_ifc.py` (realistic synthetic IFC4: storeys of slabs, walls, columns, beams, ducts and pipes, each with a property set, a style, and containment in its storey; systems per storey):

| file | elements | triangles | size | storeys |
| --- | ---: | ---: | ---: | ---: |
| `big-20000.ifc` | 20,000 | 352,000 | 17.5 MB | 8 |
| `big-100000.ifc` | 100,000 | 1,760,000 | 89.6 MB | 40 |

(These are about twice the bytes per element of the 8.2 MB / 42 MB files quoted in the task, because every element carries its own property set. 100,000 elements fit in the time budget, so 50,000 was not needed.)

"Before" is the code of this session's start (a snapshot of `web/` taken before any change, run from a copy), "after" is the working tree. Metrics: total time from `setInputFiles` to the status `Loaded ...`; longest main-thread task (`PerformanceObserver` `longtask` entries, which only report tasks over 50 ms); peak and final JS heap of the page (`performance.memory`, main thread only, sampled every 25 ms); peak and final resident memory of the whole browser process tree (`ps`, every 300 ms, workers and GPU process included); the time of the first `merged.bvh` access after the load.

**Machine noise.** This is a shared 4-core machine and other agents ran swiftshader smoke tests while these numbers were taken (load average 11 to 18 in the interleaved runs, below). Every wall-clock figure, before and after, is inflated by 1.5 to 3 times against a quiet machine; the ratios are the useful part. Before and after were run alternately so both saw the same load. Quiet-machine single runs are listed after the main tables.

## BVH serialisation

`MeshBVH.serialize(bvh, { cloneBuffers: false })` supports indirect BVHs in three-mesh-bvh 0.9.17: it returns the node buffers (`roots`) and `indirectBuffer`, and `deserialize(..., { setIndex: false })` installs them on a geometry that already owns the index. The serialised bytes are identical to what `MergedGeometry.bvh` builds lazily (`tests/large-direct.test.ts`), and a ray cast gives the same hits. Building it takes 0.46 s (20,000) and 1.4 s (100,000 elements) in the worker; before, the same build blocked the main thread on first hover or sightline (0.2 s and 1.3 s).

## Reproduce

```
python3 tools/make_big_ifc.py -n 20000  -o /tmp/xray-big-ifc/big-20000.ifc    # the bench generates missing files itself
python3 tools/make_big_ifc.py -n 100000 -o /tmp/xray-big-ifc/big-100000.ifc
BENCH_PORT=5351 node bench/bench-large-ifc.mjs --n 20000,100000 --label after              # dev app
npm run bundle && node bench/bench-large-ifc.mjs --n 20000,100000 --single --label after   # single-file build
node bench/bench-large-ifc.mjs --root /path/to/older/web --n 20000 --label before           # an older checkout, for before/after
```

Per-run JSON (stage starts, long-task list, heap and resident series, `[ifc-import]` stage timings) goes to `bench/large-ifc-<label>-<mode>-<n>.json`.
