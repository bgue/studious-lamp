## Decisions copied in (do not reopen)
- D20-22 line: the readiness read drops hidden ids from `resolve_via` and counts the visible ones only (the `total`, `ok_count` are of the visible set); keys and counts only, never record text. A twin test (hidden pinned document vs missing one) compares the whole `CheckResult`/route body byte for byte (S5 holds the pytest; the acceptance script here runs the same twin once).
- First constraint read surface (r5 dec b): every constraint route first checks the core access word `core.constraint.view` (`tl_core.constraints.commands.VIEW_WORD`, access `read`) before any lookup, with the same helper the awp read routes use for `awp.view`; a viewer without it gets the same refusal as for an unknown route target. T04d (CLI) and T09b (MCP) repeat the check at their entry points.
- Hidden looks like missing: a hidden subject's constraint answers 404 as an unknown id; list totals never count it; five-reader walk is S5's, the acceptance runs two readers.

## Names and routes (r7, from the merged reports)
- Readiness read: `tl_mod_awp.readiness.views.readiness(conn, scope, iwp_key) -> ReadinessView | None` (`None` = no IWP, hidden or never evaluated: one 404 `record_not_found`, same text for all three). `ReadinessView`: iwp_id, evaluated_at, today, ready, facts_hash, checks (`CheckResult`: name, version, state, detail, resolve_via, count_ok, count_total). The engine already rewrote `resolve_via[].key` to record ids and dropped unresolvable ones (S4 fix round): the route passes the view through and never adds a lookup. Do not return `facts_hash` (hash of facts, not a client field): map to a route model without it.
- IWP reads: `iwp_views.iwp_list(conn, scope, *, state, discipline, foreman, limit)`, `iwp_detail(conn, scope, number)`, `iwp_scope(conn, scope, number, *, limit)`; `None` detail/scope = 404 `record_not_found`.
- Constraint reads: `list_constraints/count_constraints(conn, scope, *, subject_id, state, category, phase, blocking, owner, [limit,] viewer)`, `get_constraint(conn, id, *, viewer)`, `review_groups(views, by)` with `by` in `BY_WORDS`. The API sets the viewer from the principal for the request (materials.py header), so pass none; the word check is a `guard(...)` dependency on `core.constraint.view` in the new module, as `Reader` is for `document.read`. Look up a constraint by key with one `SELECT id FROM cur_core_record WHERE scope=:s AND type='core.Constraint' AND key=:k`.
- Routes (operation ids, project path as in `routes/awp.py`): `GET /projects/{project}/awp/iwps` (`list_iwps`), `/awp/iwps/{number}` (`get_iwp`), `/awp/iwps/{number}/scope` (`list_iwp_scope`), `/awp/iwps/{number}/readiness` (`get_iwp_readiness`); `GET /projects/{project}/constraints` (`list_constraints_api`, filters as the CLI plus `subject` key, returns rows and `total` from `count_constraints`), `/constraints/groups?by=` (`constraint_groups`, `by` outside `BY_WORDS` = 422), `/constraints/{key}` (`get_constraint_api`). Declare `groups` before `{key}`.
- Readiness list over a project is not a route (an IWP's readiness is its own read; the screen tickets read per IWP).
