## Why
`tl_api/commands.py` imports each module's command table by name (`from tl_mod_awp.commands import AWP_COMMANDS` ... through
`*_module_specs(...)` rows in `COMMANDS`) and `tl_api/app.py` lists the read routers by hand. S1 declared both on `ModuleSpec`
(`commands`, `read_routers`) and added `module_commands()` returning `ModuleCommand` rows (module, model, handler, access, needs_holds,
takes_roles, meta). A new module must add `/commands/<Name>` and its read routes with no edit to `tl-api`.

## Interfaces (verbatim, `packages/tl-core/src/tl_core/modules.py`)
```python

    module: str; model: type[Command]; handler: ProposalHandler; access: str
    needs_holds: bool = False; takes_roles: bool = False; meta: Mapping[str, str] = ...
    @property
    def name(self) -> str: ...
def module_commands() -> tuple[ModuleCommand, ...]: ...   # module-name order, declared row order; clash raises ModuleLoadError
def hook_failures() -> dict[str, str]: ...                 # module -> fixed message
def resolve_hook(spec, kind) -> tuple[object, ...]: ...    # "read_routers" gives APIRouter objects in declared order
```
`tl_api.commands.CommandSpec(model, handler, access="user", *, module=None, needs_holds=False, takes_roles=False)` is unchanged.
