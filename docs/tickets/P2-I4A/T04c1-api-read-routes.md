## Goal
Four GET routes, embedded and remote, over `tl_mod_requisitions.views`. Each route checks the word `requisitions.view` first, with the helper the awp read routes use for `awp.view`, before any lookup; the viewer is the request's principal (pass none: the API sets it). Model: `routes/awp.py` IWP routes and `docs/tickets/P2-I2/T04c1-api-read-routes.md`.

## Routes (operation ids exact; project path as in `routes/awp.py`)
- `GET /projects/{project}/requisitions` (`list_requisitions`; query `kind`, `state`, `requester`, `for` = an IWP or CWP key, `limit`) returns `{rows, total}`; unknown `kind` is 422; an unknown or hidden `for` key is an empty list, the same as a key with no requisitions.
- `GET /projects/{project}/requisitions/{key}` (`get_requisition`): row, kind fields, work order or null; missing and hidden are one 404 `record_not_found`.
- `GET /projects/{project}/work-orders` (`list_work_orders`; `state`, `assigned_to`, `limit`) returns `{rows, total}`.
- `GET /projects/{project}/work-orders/{key}` (`get_work_order`): row plus `requisition_key`; one 404 as above.
Route models mirror the T04a dataclasses (same field names); ids are returned only as the dataclasses carry them; no hash. `total` is the visible row count, never a count that includes hidden rows.
