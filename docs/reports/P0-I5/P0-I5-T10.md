- `INSERT_RECORD` (`text()` with `:id, :key, :scope, :ts`): `:ts` is bound to the ISO `STAMP`; no `?` placeholders.
- Test 5 insert: `voided` is the SQL keyword `TRUE` (no `0`/`1` literal); `psets_json` is bound as text; timestamps are bound ISO strings.

- Test 6 insert: `value_bool` is bound as Python `True`; `value_num` is a bound float; `updated_at` is bound `STAMP`.
- Test 4 count: `SELECT COUNT(*) ... WHERE scope = :scope` via `scalar_one()`.

## Learnings (proposed)
- The Postgres engine registers result converters (`tl_adapters.postgres.engine`: `timestamptz` to canonical ISO text, `json`/`jsonb` to compact text, booleans as 0/1). A reader who expects psycopg's native `datetime`/`dict` will be surprised; the test relies on that conversion, so it is worth one line in the parity docs.
- A fixture named "module fixture" that requests `new_engine` (function-scoped) cannot be `scope="module"`; pytest raises a ScopeMismatch-style error. Tickets that say "module fixture" for a fixture that uses `new_db`/`new_engine` should say "module-level fixture" or give the scope.
- `just test-parity` runs `just dev up` first; without Docker it prints "skipped MinIO (no Docker daemon)" and continues. That line is not a test skip.
- `ruff check` (E501) counts the docstring quotes; a one-line docstring must be 100 columns or fewer including `"""`.
- AGENTS.md's tier table lists `docs/build-spec/01-tiers.md` §4 for implementers; the ticket's Context list did not include it, so I followed the Context list only. Nothing in the ticket depended on it.
