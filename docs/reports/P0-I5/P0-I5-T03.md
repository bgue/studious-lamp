## Learnings (proposed)
- Running `sed -i` on a file after reading it makes the harness reject the next `Edit` on that file ("File has been modified since read"). I hit this on the first conversion attempt. Do the sed step after the Edit calls, or re-read the file before editing. The ticket's recipe lists the sed as step 2 and does not warn about this.
- Recipe item 2's `sed 's/\bdb: Path\b/db: DbTarget/g'` changes parameter annotations only. Fixture return annotations (`def db(...) -> Path:`) must be edited by hand, which the recipe does say ("check `-> Path` return types ... by hand"). The fixture-return edit is the one the recipe's example shows, so keep it in the same Edit as the fixture body.
- `just test-parity` for these three files reports `92 passed, 1 deselected`, not 93. The gap is `test_stream_ids`, which has no adapter fixture. A reader comparing against the 93 total could mistake it for a skip; it is not one.
- `just dev up` prints `skipped MinIO (no Docker daemon); the fs object store is used instead`. This is harmless for these tests.
