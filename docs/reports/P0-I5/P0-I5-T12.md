## Learnings (proposed)
- `sudo pg_ctlcluster 16 main start` on a cluster that is already running exits 2 with `Cluster is already running.`. The ticket's step did not say this, so a reader could take it as a failure. The runbook now says it is harmless and that `pg_isready` is the check that matters.
- Several worktrees and agents share one Postgres server. The leftover-database listing showed a live `tl_pytest_*` database owned by another run, so the manual cleanup pattern cannot tell live from stale. Recommend the runbook keep the "no test run in progress" condition, and that a supervisor checks for running pytest processes before any manual drop.
- `just test-parity` prints `dev up: skipped MinIO (no Docker daemon); the fs object store is used instead` before the tests. It is harmless, but a reader may take it for a Postgres problem.
- `just test-parity tests/services/test_record_commands.py` reports `46 passed, 3 deselected`. The output gives no reason for the 3 deselected tests, and the ticket does not mention them. Not investigated (out of scope).
- The compose `postgres` service publishes host port 5432. On a machine that also runs the native cluster from ADR-0002, the two collide. The runbook does not warn about this; a note may be worth adding.
