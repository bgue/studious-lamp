## Learnings (proposed)
- The ticket says "3 pure-parser tests stay unparametrised (7 -> 10)". The file actually has 4 pure tests (`test_parse_returns_an_ast_or_raises_query_syntax_error`, `test_parse_survives_arbitrary_unicode`, `test_to_text_round_trips`, `test_whatever_parses_prints_and_parses_again`) and 3 database tests. 4 + 3×2 = 10, so the total in the table is right; the "3" in the wording is not. A reviewer counting by hand should expect 4 unparametrised tests.
- For `test_injection.py`, the 126 on Postgres is 62 database-using tests × 2 plus 2 pure tests (`test_quote_and_to_text_round_trip_hostile_strings`, `test_a_quoted_date_with_a_trailing_newline_is_a_syntax_error`). The pure tests never take an adapter fixture.
- Tool quirk: running `sed -i` on files that were already Read made the Edit tool reject the next edit with "modified since read". Re-read the file before editing again, or do bulk renames last.
- Wall-clock cost: `tests/query` takes about 70 s on SQLite and about 7 minutes with `--adapters sqlite,postgres`. Plan the timeout for that second command accordingly.
- No text-ordering or case-folding difference between SQLite and Postgres showed up in these five files. The ordering assertions (`test_order_by_envelope_columns_puts_empty_values_last`, `test_default_order_is_creation_time_then_id`, the `title` asc ordering) and the `BEVEL`/`weld` text-search cases all passed unchanged on Postgres.
