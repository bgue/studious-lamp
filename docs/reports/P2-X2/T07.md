# P2-X2-T07 report: blocked on a design question (no code change)

## Finding
`Agent.Stopped` / `Agent.Resumed` cannot reach a webhook subscriber, by design (ADR-0009).
`packages/tl-core/src/tl_core/webhooks/dispatch.py` `SubscriptionRow.receives` returns False for every
row whose `stream_type == "core.Account"`, "whatever the filter says". The two events are appended on
the account stream (see `auth/projector.py` `STREAM_BUMP_EVENT_TYPES`).

## Evidence
I extended `run_scenario` through the real commands (admin person account, agent account, `user` grant on
`project:P1`, one `submit`, then `handle_stop_agent` and `handle_resume_agent`). Both events were
appended. The first contract test still failed: extra items in DELIVERABLE were exactly
`Agent.Resumed` and `Agent.Stopped`. The scenario change was reverted, as it cannot make the test pass.

## Cause
`DELIVERABLE` in `tests/contract/test_webhook_catalog_contract.py` removes `ACCOUNT_EVENT_TYPES`, which
does not list the two S3 events (they are in the separate `STREAM_BUMP_EVENT_TYPES`). The test's
exclusion is stale, not the delivery.

## Proposed test change
In `DELIVERABLE`, also subtract `STREAM_BUMP_EVENT_TYPES` (import from `tl_core.auth.projector`) and
update the comment: account-stream events, including `Agent.Stopped` / `Agent.Resumed`, are internal.
Optionally add an assertion that neither appears in `delivered["thin"]` after the scenario stops and
resumes an agent (a guard that admin-only account events stay unsent); that needs the scenario
extension above (about 40 lines in `tests/webhooks/scenario.py`).
A product-side alternative (one constant for all account-stream event types) is outside this ticket.

## Gate
Not run (no code change). Commits: ticket only.
