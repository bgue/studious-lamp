## Learnings (proposed)
- The MCP `update_psets` tool stamps the record's current version into the command when `expected_version` is omitted (`write_tools.py`, `expected_version if ... else found["version"]`). The idempotency body hash includes that field, so any change of the record's version between filing and retry turns a keyed retry into `IdempotencyMismatch`, not a replay. The keyed retry after a move or void therefore fails for a reason other than precheck.
- `CreateRecord` over the API refuses a type that is not in the extension-type service (`unsupported_record_type`), so `use_modules` alone does not make a record type available to HTTP tests.
