## What changed
- `idempotency.lookup(conn, actor, key, command, body)`: read-only twin of `check`. No key, no entry or an unfinished entry gives `None`. A completed entry with the same command and body hash gives a `Replay`. A different command or hash raises `IdempotencyMismatch` (the fixed text). Nothing is written.
- `proposals.submit`: when `command.idempotency_key` is set, it looks up (agent, key) in a read before the budget check and `precheck`. A replay re-reads the proposal id through the viewer filter (hidden looks absent) and returns the stored proposal, with no budget use, no dry run and no event. With no key or no entry the order is unchanged. The claim inside `propose` stays the authority for racing first filings.
