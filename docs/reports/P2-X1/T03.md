## Deviations
One interface change, as the ticket's amendment (orchestrator, 2026-11-14) directs: the `IdempotencyKey` alias in `write_tools.py` no longer has `pattern=r"^[\x21-\x7e]+$"`. `min_length=1`, `max_length=128` and the description are unchanged. Reason: FastMCP echoes the rejected value into the error text for a `pattern` violation, which breaks the no-echo rule. Printable-ASCII-without-space is still enforced by command validation (`KEY_PATTERN`, `KEY_REFUSED` in `tl_core.services.commands`), which does not echo the key.

## Learnings (proposed)
- FastMCP puts the rejected value (`input_value=...`) into the tool error text for a `Field(pattern=...)` violation. Any `pattern=` on a secret-like input leaks it. `max_length` does not leak. Command-level validation does not leak.
- The earlier attempt read `proposals.submit` and reported that the budget check and `precheck` run before `propose`'s idempotency replay, so a keyed retry could be refused by the budget or the dry run instead of replaying. Not verified or tested in this ticket; worth a check before T03b.
