## Learnings (proposed)
- FastMCP's argument validation puts the rejected value (`input_value=...`) in the tool error text for a `pattern` violation. Any `Field(pattern=...)` on a secret-like input leaks it. `max_length` does not leak. Command-level validation (`hide_input_in_errors`, `KEY_REFUSED`) does not leak.
- Reading `proposals.submit`: the budget check and `precheck` run before `propose`'s idempotency replay. A retry of a keyed proposal may therefore be refused by the budget or by the dry run, instead of returning the first proposal. Not tested here.
