# Risk register after Phase 1

Purpose: the brief §17 register brought up to date with what Phase 0 and Phase 1 showed, plus the risks the build run itself found. Phase 0 rows were written 2026-10-11 by the P0-I8 workstream E supervisor; Phase 1 evidence was added 2026-10-20 at the Phase 1 exit (changes listed in `docs/adr/0020-phase1-risk-register.md`). Evidence is a report, learning (`L-…` in `docs/memory/LEARNINGS.md`), ADR or file. Performance figures are from `docs/reports/P0-I8-perf.md` (100,000 records, 360,455 events, two runs, SQLite and Postgres 16 on a shared four-CPU container) and have not been re-measured. Risks that Phase 2 will meet are ranked in `docs/build-spec/phase2-risks.md` (R-P2-1 to R-P2-20) and are cited here, not copied. Rows whose status depends on P1-I8 (R12, R13, R14, R17) say so; the orchestrator confirms them after P1-I8 merges.

Scales: likelihood and impact are L (low), M (medium) or H (high) as judged for a first customer project. Owner is **human** (a decision or action only the owner can take; most are `04-gates.md` §2 gates) or **agent** (the build agents can do the work). Status: open, mitigated (a control exists and is tested), monitoring, accepted (a decision to live with it), not started (the area has not been built).

## 3. Reading the register

The risks that should decide the next phase's ordering, in order:
1. Q5/Q6, X11 and X10 (deployment): accounts, three roles and confidentiality classes exist, but Entra ID, project roles, a front-door rate limiter, secrets at rest and external parties do not. Everything customer-facing waits on them. All are the owner's.
2. R12 and X15 (schema change and upgrade): Phase 1 changed the schema many times, always additively and by hand-approved merge; the classification gate and a rebuild or migration tool decide whether the first breaking change is safe.
3. R4 (extraction accuracy): the pipeline and the review gate are built, the content extractors are stubs. Build a golden set of real PDFs before any provider is plugged in.
4. X24 to X26, R10, X3, X4 (agent-written code and untrusted input): the controls work and are expensive; every new door still finds a HIGH on first review. Keep them.
5. X13, X8, R1 (speed and write throughput): the suite takes hours, parity does not fit a background run, the write lock and the 100k rebuild are unmeasured since Phase 0.
6. X12 (CI never ran): cheap to close, and the only gate that is not observed.
