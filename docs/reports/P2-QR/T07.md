## Learnings (proposed)
- In the QR test ledger, `user` and `document_controller` both hold `qr.view`, and an account needs at least one role (`InvalidAccountError`). So there is no roled account without the view word. The "no view word" miss is simulated by patching `resolve.view_word_held` for one account. A roster change that adds a role-free account would remove the need.
- `service.value_of` is re-exported only implicitly, so pyright flags it as a private import. Patching it in tests works only if the CLI calls `service.value_of`.
