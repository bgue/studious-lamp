# P2-QR-S3: the scan page `/web/q`, the miss counter, the log filter

## Deviations (first)
1. **Signed-out bounce is a 303, not a rendered page.** `AuthenticationMiddleware` (`tl_api/auth.py`, outside
   the allowed paths) already answers every signed-out `GET` under `/web/` with a 303 to `/web/sign-in`, before
   any route runs. So no resolver call and no statement happen for a signed-out request, by construction. The
   outer `WebHeadersMiddleware` (`app.py`) rewrites that one Location to `/web/sign-in?next=<path>` when the
   segment, upper-cased and ASCII, matches `[A-Z0-9]{16}`; a malformed segment gets plain `/web/sign-in`.
   Consequence: a well-formed code appears in the sign-in URL's query (the visitor typed it). The log filter
   redacts `next=/web/q/...` (plain and `%2F` encoded) too. The sign-in page itself keeps `same-origin`.
2. **Agents get 401, not the guard's 403**: the middleware refuses an agent token under `/web/` first
   ("agents have no web session"). `guard("qr.read")` is on every route and is the second wall.
3. **Files outside the list, minimal edits:** `templates/base.html` (the two script tags wrapped in
   `{% block scripts %}`, output unchanged; `scan.html` empties it so the card has no `<script`),
   `templates/sign_in.html` (hidden `next`), `tests/test_web_imports.py`, `tests/test_web_csrf.py`,
   `tests/walk.py` (pins below).
4. Access log filter also catches the sign-in `next=` value (item 1); installed in `started_server` after
   `uvicorn.Config` (which configures the loggers).

## Pins moved

- `walk.NO_RECORD_TEXT` gets `GET /web/q/{code}` (walked as five readers in `test_scan_page.py`).
- `route_order`, openapi, `test_auth_review` sets: unchanged (web routes are out of the schema; `qr.read` already listed).

## The miss page, byte-equal evidence
`test_five_readers_one_card_or_the_one_miss`: for the plain user and the admin, a malformed, an unknown, a
revoked, an expired, a hidden, a no-view-word and a no-provider code give the same status, bytes and headers
(one session each). Across readers the bytes differ only by the session's own CSRF token. No `Set-Cookie`.

## Limits
`MISS_LIMIT_SESSION = 10`, `MISS_LIMIT_ADDRESS = 30`, `WINDOW_S = 600`, `MAX_KEYS = 10_000`. Limited when
count >= limit, so the 11th lookup gets 429. Keys: sha256 of the token, and the address from
`ratelimit.client_key` with `settings.trusted_proxy_header`. 429 text: `scan.LIMITED_TEXT`.
A typed malformed code on `POST /web/q` counts as a miss.
