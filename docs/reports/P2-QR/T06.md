## Blocker (the route cannot be written inside Allowed paths)
The ticket requires the routes to use `guard`, `current_principal` and `get_ctx` from `tl_api` (the punch pattern). `tl_mod_qr/routes.py` is a module file, and two facts block that:

a) Dependency. `packages/tl-modules/qr/pyproject.toml` declares no `tl-api` (deps: pydantic, sqlalchemy, tl-core, tl-schema, tl-adapters, fastapi, mcp, typer). Importing `tl_api.auth` / `tl_api.context` from `tl_mod_qr` is a new undeclared dependency and an import from a module into the API layer. No `tl_mod_*` package imports `tl_api` today (grep of `packages/tl-modules/*/src`).

b) Location. Moving the routes to `packages/tl-api/src/tl_api/routes/qr.py` does not work as things stand. `packages/tl-core/src/tl_core/modules.py` `IN_TREE_SURFACES` lists only `awp, correspondence, cost, documents, engineering, legacy, materials, quality, requisitions, schedule, schemareg`. `qr` is not in it, so `_check_ref` refuses a `read_routers` ref under `tl_api.routes.` for qr (`ModuleLoadError`). The fix is a tl-core change outside Allowed paths.

Checked and not changed: `guard("qr.read")` is not declared in `schema/settings/access-words.yaml` (only `qr.view`, `qr.issue`, `qr.revoke`) or any agent list I found by grep; whether the closed guard refuses an unlisted action for agents is unverified.
