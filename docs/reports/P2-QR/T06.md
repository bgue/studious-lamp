## Learnings (candidate)
- No account can lack `qr.view`: `schema/settings/module-roles.yaml` derives `user` (words `read`, `user`) for every module, and `normalise_word("qr.view")` is the table word `read`. A "no view word" 403 cannot be reached with real data; test it at `require_word`. Worth a line in the QR ticket template.
- `create_account` refuses a person with no role, so "signed in, no role" cannot be seeded.
- A `Cache-Control` header set through the injected `Response` does not reach an error answer; the route builds its 404 with `body_for` and sets the header itself. Guard refusals (401, 403) still come from the shared handler without `no-store`.
- A heredoc to `uv run python -` hung the shell tool until its PID was killed; use a script file with `</dev/null`.
