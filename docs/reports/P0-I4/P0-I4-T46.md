## Learnings (proposed)
- `just check` prints no line for `python -m tl_api.openapi --check` when the spec is up to date; the success signal is the exit code (0), not output text. Worth stating in the runbook so an empty line is not read as a skipped step.
- The ticket's Context list does not name `packages/tl-api/src/tl_api/client/__init__.py`, yet the provided test imports `ApiClient` from there and it is what composes `RecordsApi`. It already composes it on the branch point, so no change was needed; the Context list could name it for future tickets of this kind.
- `ApiClientBase._send` drops only `None` params, so `include_voided=False` is sent on every `list_records` call as a literal `false`. The provided tests pass with this, so it is the intended behaviour, but it is not stated in the ticket.
