## Learnings (proposed)
- Under machine load, `packages/tl-api/tests/test_stream.py::test_an_in_process_write_reaches_the_stream` ran for 27+ minutes with no output and no failure (pytest blocked in the poller's wait). Alone it takes about 7 s, and the full suite passed on rerun. A timeout on the stream tests, or a note that they can hang under contention, would save the next implementer that wait.
- A wait loop `until ! kill -0 <pid>` exited at once while the process was still running (cause not checked). `while [ -d /proc/<pid> ]` waited correctly.
- Redirecting `pytest` output to a file in the scratchpad and waiting on a sentinel line (`EXIT=`) avoids the 120 s foreground limit and keeps the full output.
