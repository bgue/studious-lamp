## Deviations
Two files changed, both inside Allowed paths. Deviations from the ticket text, each deliberate:

1. The ledger copy opens the source with `sqlite3.connect(f"{path.as_uri()}?mode=ro", uri=True)`
   instead of the literal `f"file:{path}?mode=ro"`. `as_uri()` percent-encodes the path, so a dev
   file whose name holds `?`, `#`, `%` or a space still opens. The read-only mode and the backup
   are as the ticket says.
2. Textual accepts any string as a key (`pilot.press("nokey")` returns without error; checked
   with a probe). The ticket requires a `ToolError` for an unknown name, so the tool checks each
   name first with `_is_key_name`: modifiers (`ctrl+`, `shift+`, `alt+`, `meta+`) over a single
   character, a name in Textual's own key tables (`textual.keys.Keys`, `KEY_NAME_REPLACEMENTS`,
   `KEY_TO_UNICODE_NAME`), or a Unicode character name in Textual's lower-case-with-underscores
   form. The failure is `DevToolFailure("unknown key name 'nokey': use Textual key names ...")`.
3. `ScreenOutput.svg_truncated` defaults to `False` and is set to `True` when the SVG is over
   400000 characters (the ticket's `= True` read as the value set when truncated). The file always
   gets the full SVG; only the answer's `svg` is emptied.
4. A `sqlite3.Error` during the copy becomes `DevToolFailure` with the exception class name only,
   so no path from SQLite's message reaches the client. The ticket did not name this case.
5. The timeout test stubs `_screen` with a coroutine that sleeps, instead of a real app, and
   sets `SETTLE_TIMEOUT_S` to 0.05 s. A real app cancelled mid-startup leaves Textual's
   `Screen._watch_selections` coroutine unawaited, which surfaced as a `RuntimeWarning` in an
   unrelated test (`test_dev_run_tests.py`) before this change. The test still covers the path
   the ticket names: the timeout becomes `DevToolFailure("... did not settle ...")` and the
   temporary directory is removed.
6. The test file has more tests than the ticket's list: key-name parametrized tests and the
   timeout test (both listed above) and the four refusal cases as one parametrized test. Nothing
   from the ticket's list is missing.

## Learnings (proposed)
- Textual's `Pilot.press` accepts any string as a key and never raises for an unknown name; a
  tool that takes key names must check them itself (`_is_key_name` in `tool_render_screen.py`
  shows the rule: Textual's `keys` tables plus Unicode character names).
- Cancelling `app.run_test` during startup (a short `asyncio.wait_for`) leaves Textual's
  `Screen._watch_selections` coroutine unawaited. The `RuntimeWarning` appears later, in whatever
  test the garbage collector is running. Test timeouts by stubbing the run, not the app.
- `asyncio.TimeoutError` is the builtin `TimeoutError`, an `OSError` subclass. In `guarded`, the
  `OSError` branch would turn it into a generic `OSError: ...` message unless the tool catches
  `TimeoutError` first (the tool does).
- `sqlite3.connect(f"file:{path}?mode=ro", uri=True)` breaks for a path containing `?`, `#`, `%`
  or a space. Use `Path.as_uri()` plus `?mode=ro`.
- The ticket's `tests/helpers.screen_text` lives under `packages/tl-tui/tests`, which `tl-mcp`
  tests cannot import. The two lines are copied into the tool, with the one pyright ignore and
  a comment, as the ticket asks.
- The dev server test for `main.py` writes `dev/data/dev-mcp.log.jsonl` into the real repository
  when the full `packages/tl-mcp` suite runs (git-ignored; pre-existing, not from this ticket).
- The first `uv sync --all-packages | tail -5` in this worktree reported exit 2 although its
  output was normal installation lines. A second run exited 0 with `Checked 155 packages`. The
  cause was not found.
