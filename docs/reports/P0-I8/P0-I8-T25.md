## Learnings (proposed)
- `FieldEditor.validate()` only sets an error for typed text (Input). For Select and Switch it returns `self._error is None` and never clears; `_raw_changed` calls it too. So a "Required" mark set on a choice field stays on screen after the user picks a value, until the next save. The modal works around this in `_check` (clears first); the widget itself is outside this ticket's allowed paths. Candidate fix for the supervisor in `form_fields.py`.
- A `Switch` always has a value (`False` when untouched), so a required bool slot can never trip the "Required" check, and an untouched bool is sent as `False`, not unset. See Open questions.
- Tool quirk: `Edit` refuses a file that was only read through `cat` in Bash ("File has not been read yet"); reading it with the Read tool first fixes it.

## Open questions / Blocked
Not blocked; the ticket's acceptance is met. Three points for the supervisor:
1. An untouched bool slot is sent as `False`. The modal collects `{name: editor.value}` as the ticket says, `FieldEditor.value` for a Switch is `False` when untouched, and `split_values` keeps every non-`None` value. So an optional bool that the user never touched is stored as `false`. The fix would be to collect `editor.value if editor.changed else None` in `action_save`, which the ticket does not say. Not changed here; needs a decision.
2. For an object-backed type `split_values` returns `psets={}` (an empty dict, not `None`), and `action_save` passes it as `psets=split.psets`, as the ticket's stub comment says. The fake accepts an empty dict. The brief says `psets` "must not be given" for object-backed types, so the supervisor may want `psets=None` in that case. Not changed here.
3. The stale "Required" mark on Select/Switch (see Learnings) is cleared only at the next save. The real fix belongs in `widgets/form_fields.py`, which is outside this ticket.
