## Learnings (proposed)
- A timed-out seed is a normal tool result, so its audit line says `outcome: ok` while the returned `timed_out` is true. Anyone scanning the audit file for failures will miss timeouts. The supervisor may want a distinct outcome.
- The API that `seed.sh` starts sits in its own session, so `killpg` on the tool's process group does not reach it directly. Cleanup depends on the script's `EXIT` trap running on SIGTERM; it did in every probe, but that is the thing to watch if the script changes.
- Running the full tl-mcp suite leaves `dev/data/dev-mcp.log.jsonl` in the worktree. It is git-ignored and comes from the existing dev-server tests, not from this change.
- `pgrep -af '...'` matched the calling shell's own command line; `ps -eo pid,pgid,sid,args | grep '[t]l serve'` is the reliable check.
