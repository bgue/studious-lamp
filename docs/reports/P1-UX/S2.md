## Detail getters: envelope to arguments (the table the screen tickets use)
`project` = `project_of_scope(record["scope"])` (the id without `project:`). The key is the number in every row except clock and snapshot.
| Getter | Type | Arguments from the envelope | Key is the number? |
|---|---|---|---|
| `get_document` | documents.Document | `(project, key)` | yes |
| `get_tag` | engineering.Tag | `(project, key)` | yes |
| `get_correspondence` | correspondence.Correspondence | `(project, key)` | yes |
| `get_rfi` | correspondence.TechnicalItem | `(project, key)` | yes |
| `get_commercial` | correspondence.CommercialItem | `(project, key)` | yes |
| `get_clock` | correspondence.ResponseClock | `(project, record["id"])`; key is `<item number>-C01`, not the clock id | no, takes the record id |
| `get_schedule` | schedule.Schedule | `(project, key)`; key is the code | code |
| `get_schedule_snapshot` | schedule.ScheduleSnapshot | key is `CODE#N`: `(project, code, int(N))` | no, composed key |
All eight are callable from `(scope, key)` plus the id: no escalation. Types on generic rows now: every type except documents.Document.

## Learnings (proposed)
- `mode_of` takes the app (or an object with `display_mode`), never a widget; a widget call silently gives plain mode.
- A `DataTable` consumes Enter before a screen binding; a register stand-in needs `priority=True` or the row-selected event.
