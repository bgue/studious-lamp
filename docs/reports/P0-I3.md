## Deviations from plan
Decisions D1 to D28 are in `docs/tickets/P0-I3/README.md`. The ones a reader must know:
- **D5:** link counts are in `cur_link_counts`, not columns on `cur_core_record` (the plan said the latter; build spec 03 §9 freezes that DDL).
- **D8:** gap-free numbering means a number is allocated only inside the transaction that creates the record; counters are ledger streams; the counter stream's expected-version check is the second line of defence. Reading of open question Q7; the orchestrator accepted it.
- **D11, D12:** a record with no workflow state is in the initial state; roles are a caller-supplied stub list until auth exists.
- **D18:** a broken link has no direct route back to active (stale, then repin, or retract).
- **D22:** the grid link-count column waits for the P0-I4 query language; counts show as record-view badges.
- **D25:** `EditRecord` composes the existing handlers in one unit of work. An edit in which every part is a no-op raises `NoChangesError` even when `expected_version` is stale.
- **D26 to D28:** `tl link trace` added after T14a; partly refused tray batches stay open; `1 link` wording.
- `pyyaml` is a direct dependency of `tl-core` (D15). `CreateRecord` gained the optional `numbering` field (additive). `ClientInterface` gained link, search, workflow, key-detection and `edit_record` methods (additive).
