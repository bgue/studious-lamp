## How the screen gets the new receipt id
`materials_command("CreateReceipt", ...)` returns a `CommandResult` whose `stream_id` is the receipt record id and `key` its number (S6.py asserts `stream_id == receipt_detail.id`). No field added; `RemoteClient` serves the new method through `__getattr__` (signature equals the interface).

## Behaviour worth knowing
- Hidden and missing records raise `RecordNotFoundError` with the same text (embedded and API; S6.py compares them with the id masked). The service re-checks hidden, so the embedded pre-check is for the scope.
- `FileResult.status` is `available` (inline scan on); after Accept the materials guard refuses a repeat MTR attach ("an accepted receipt takes only certificate and photo files"), so the same-bytes retry is only idempotent before Accept.
- The word check is the service's (`require_generic`, `user` word for the record's module on its scope). An account-less actor holds it on a SQLite dev ledger only; S6.py creates account `alice` (role `user`) on both backends, and uses `svc:no-words` as the person without the word. The API client's 403 path was not exercised (no second token with an account lacking the word).
- TUI start-up: the embedded client needs `object_store=` (or `files=`) and `TL_OBJECT_SECRET`, or `TL_ENV=dev`; otherwise `BodyStoreUnavailableError`, as `fetch_file`.
