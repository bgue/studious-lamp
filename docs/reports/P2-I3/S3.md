## Deviations
1. **`Rule` lives in `actions.py`** (rev 2; the extra `rules.py` is gone). `actions.py` imports `MTO_RULES` from `mto.py`, so S4's rows are
   a type of their own; `RULES` is `tuple[object, ...]` and `rule_rows()` reads every row by shape (`record_type`|`type`, `condition`, `label`,
   `command`|`command_name`, `word`), as S4's spec says. The first commit's subject lacks the `P2-I3-S3:` prefix; history is not rewritten, this commit has it.
2. **`openapi.json` is `docs/reference/openapi.json`** (not `packages/tl-api/openapi.json`); regenerated. The orchestrator regenerates it again at merge.
2a. `receipts(missing_mtr=True)` now filters in SQL (no required MTR file and a line in a required category), so `LIMIT` counts only qualifying rows.
3. Names the spec left open: receipt commands take `stream_id` (+ `expected_version`, required for Accept only); `Movement` has `from_location` /
   `to_location` (codes; `from` is a keyword); `api.PostedMovement` adds `kind`, `scope`, `requisition_id`; `post_movements` returns the event ids and
   takes optional `correlation_id`/`causation_id`; `by_module` is accepted and loosens nothing (movements are module commands, there is no allow-list row to skip).
4. Rules I chose where the spec is silent: Accept needs state Inspected (workflow); a receipt with a PO line carries that line's item only; a library item
   not yet adopted is adopted by the receipt (source `rule`); every `to` location must be active; fields a kind does not take are refused (`to` on issue, `direction`
   off adjust, `cost_code_id` off non-issue); reserve checks `line.reserved + qty <= line.qty` literally (issued is not added); `Reject` is `materials.receipt.decide`.
5. `need_by` of `views.MtoLineView` is always `None`: the awp module is not in this tree. The "Assign" row of section 6 is S4's `MTO_RULES`; the "Reserve from a lot" row is in `RULES`
   (a repeated command on one record is offered once).
6. New error classes (appended to `errors.py`): `ReceiptNotFoundError`, `ReceiptStateError`, `MtrRequiredError`, `CostCodeNotFoundError`, `MovementRuleError`, `InsufficientStockError`.

## Learnings (proposed)
- A SQLite `open_uow` takes `BEGIN IMMEDIATE` on entry: a barrier inside the `with` deadlocks two writer threads; put it before.
- `AGENT`/`USER`/`BOSS` module-role holders can be built with `Holder(account_id="dev:<actor>")` and passed to `require_command_access`, with no accounts in the ledger.
- A hand-made `awp.IWP`/`cost.CostCode` record (`Record.Created` only) is enough for the movement checks, which read type and key only.
