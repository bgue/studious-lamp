## Open questions / Blocked

The spec's escalation trigger "the publish pipeline cannot reverse a target's records itself (a `documents` change beyond decision 5)" holds. Reading `tl_mod_documents/derivation/` on `p2/i3` shows three gaps, none inside decision 5:

1. **No compensation hook (decision 4 assumes one).** `PublishTarget` (`publish_targets.py:41-66`) has `name`, `module`, `record_type`, `plan_rows`, `create`; no reverse method. `handle_compensate_publication` / `preview_compensation` (`publish.py:694-884`) never ask the target. `_record_item` (`publish.py:741-795`) knows only `engineering.Tag` (workflow `delete`) and `documents.Document` (`VoidDocument`); any other type gets `reversible=False`, problem "a materials.MTO cannot be rolled back by this command", so the whole compensation refuses. A published MTO could therefore never be compensated, and the spec's "compensation without a reservation removes MTO and lines; republish after it" cannot hold. The `MtoLineInUseError` refusal (reserved or issued) also has no place to be called from.
2. **Mapping rejects an `mto` target.** `mapping.check_mapping` (`mapping.py:95-120`) refuses any target outside `names.TARGET_KINDS = ("tags", "documents")` and picks the allowed fields from `TAG_FIELDS` / `DOCUMENT_FIELDS`; the mapping JSON format (`_format_schema`) probably enumerates the same two. Decision 5 widens only the `RegisterDocumentSchema.target_kind` type at `schemas.py:77`, so an `mto` document schema with a mapping still fails `check_mapping` at schema registration (`schemas.py:239`) and in `_build` (`publish.py:246`). Acceptance defines the schema "through the documents command", so this path is required.
3. **Private plan types.** `plan_rows` must return `(PlanRow list, creatable list, counts)`; `_Creatable`, `_Built` are private to `publish.py`, and `_create_*` read `built.creatable[i].fields/.psets`. A materials target can return `PlanRow` (public) and its own creatable objects (the protocol types them `Any`), so this one is workable but fragile. Also `_provenance_problem` (`publish.py:198`) needs the effective schema's `src` provenance pset to list `materials.MTO` in `applies_to`; that is schema data (`schema/**`, not mine) and must be checked in the fixtures.

Question for the orchestrator (a decision I will not guess, per AGENTS.md rule 8): approve a small `documents` change beyond decision 5, which I propose as:
- (a) add an optional hook to the `PublishTarget` protocol, for example `compensation_item(conn, record_id, scope) -> (reversible, problem)` and `reverse(uow, base, record_id, reason)`; make `_record_item` and `handle_compensate_publication` dispatch on `record_type` via `publish_targets()` before the `unknown` fallback (tags and documents keep their code). The `mto` target then refuses with `MtoLineInUseError` text in `problem` and voids lines then the MTO in `reverse`.
- (b) let `check_mapping` accept any registered target name (`publish_targets()`), with the mapping field set supplied by the target (for example a `mapping_fields` attribute), and widen `TARGET_KINDS` use accordingly.
Or: re-scope S4 to publish plus `AssignMtoLines` only, and give compensation to a documents piece. Either way the spec's Allowed paths need to name the extra `documents/**` files (`publish.py`, `publish_targets.py`, `mapping.py`, `names.py`).
