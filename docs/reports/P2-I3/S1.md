## Deviations
1. `cur_materials_stock.available` is a stored decimal column, not a view column: the DDL generator has no
   computed column and builds a `v_*` view only for record classes (`tl:record_types`); a hand-written view is
   forbidden. The projector (S2) writes `available` with `on_hand` and `reserved`. If a true view is wanted,
   the generator needs a feature (outside this piece). See open question 1.
2. `dev/accept/P2-W0/OC-S1.py` (not in Allowed paths) gained the eight `materials.*` rows in `EXPECTED_RECORDS`;
   the spec's Context names it as "the pin you extend", and without it that script fails.
3. Added columns beyond section 2, needed by the generator: `scope` on the projection tables and the receipt
   line, `row_id` on `cur_materials_receipt_line`, `last_seq` on records; unique indexes stand in for
   composite primary keys on `cur_materials_stock` and `cur_materials_reservation`.
4. Quantities use LinkML `decimal` (SQL `NUMERIC`), not text: the generator has a decimal type. On SQLite
   NUMERIC affinity stores `12.500` as REAL `12.5`; exact for 3 decimals up to 1e9, S2 must read it as `Decimal(str(x))`.
   Event payload quantities are text with a shape pattern; the range (> 0, <= 1e9) is the command's check (S2).
