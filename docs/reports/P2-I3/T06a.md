## Learnings (proposed)
- The stored kind for a receipt is `receive` (`tl_mod_materials.names.RECEIVE`), not `receipt`. `views.movements(kind=...)` accepts only the `MOVEMENT_KINDS` set, so a filter keyed on `receipt` returns no rows silently. The ticket and any later text should say `receive`.
- Receive movements in the seed ledger carry `direction = None`, so their quantities print unsigned (`12`), not `+12`.
- `just check` ruff limit is 100 columns, and it counts docstring and comment lines; `ruff format` does not wrap them.

## Open questions / Blocked
1. **Kind key (needs supervisor decision, not changed here).** `KIND_WORDS` follows the ticket literally (`receipt` → Receipt). The ledger stores `receive`, so a real receipt shows as `Receive` (humanized) and a Receipt kind filter built on `KIND_WORDS` keys matches no rows. Proposed fix: key `receive` → `Receipt` (and keep the others). Not done without approval.
2. **Unsigned receipts.** Under the ticket's rule (`in` +, `out` -, else unsigned) receive rows print `12`. Confirm this is wanted, or that the receive writer should set `direction = in`.
3. **Movement Lot cell.** The ticket does not say; I used heat-or-key, matching the stock log. Confirm.
4. **Empty-state notes.** `No stock on hand` (Quantities) and `No movements` (Movements) are my wording; the ticket gives only `No reservations`.
