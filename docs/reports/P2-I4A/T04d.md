## Deviations
1. `--actor` (default `user:dev`) added to all four reads. The brief's signatures do not list it, but the ticket requires the word check "for the actor", and `constraint_read` and the T04e1 writes both take it. Behaviour otherwise as briefed.
2. `req ls --kind X` with an unknown kind is a usage error (exit 2, `BadParameter`), because `requisition_list` raises `ValueError`. The ticket is silent on this.
3. The commit trailer names the implementer's own model, not the one the ticket names (same mismatch as T04e1).
4. `--for` resolves any record by key (`get_record`), not only `awp.IWP`. The brief says "IWP number" without a type check; I did not add one.
5. Refusal test uses `--actor agent:nobody`, not `user:nobody`. On a dev ledger file every `user:` actor holds the `user` role, which carries the `read` word, so `requisitions.view` is granted to it. "Before any SELECT" is read as "before any requisition table is read": the holder lookup itself reads `cur_*` role tables.
6. Read order: `acting` and `require_view` run in one unit of work, then `session_viewer`, then the view read. Same effect as `constraint_read.enter` with the viewer fetched later.

## Learnings (proposed)
- On a dev ledger file, every `user:` actor holds the `user` role (words `read` and `user`). A "forbidden" test for a read word needs an `agent:` actor, or a ledger that is not the dev file.
- `req.py` docstring still says "the reads of T04d join later"; left as is (outside Allowed paths).
- The seed helpers are now duplicated in `test_req_write.py` and `test_req_read.py`. A shared `tests/req_cli_seed.py` would remove the copy.
