## Learnings (proposed)
- `tl pset set` needs the pset in the project's effective schema. The P123 package extends only `valve_data`, so `crane_lift` is refused. Without a pin the error does not say which package to pin.
- Every account has at least one role. The account role `user` derives `user` in every module, and every module role holds `read`, which is `requisitions.view`. So no person created by `tl admin user add` lacks the word, and `tl admin user roles --remove user` is refused.
- The MCP list and get tools for requisitions check no access word; the shared authorise hook is allow-all. The API route does check the word.
