## Learnings (proposed)
- `tl pset set` needs the pset in the project's effective schema; P123 extends only `valve_data`. The error does not name the package to pin. The TL_SCHEMA_DIR copy is the workaround for the demo only.
- Every account has a role; account role `user` derives `user` in every module, and every module role holds `read`, so no account can lack `requisitions.view`.
- The MCP requisition list and get tools check no access word; the shared authorise hook is allow-all in production paths. The API route does check it.
- Waiting on a backgrounded `just demo` by `pgrep -f` is unreliable; waiting for an exit-code line in the log file worked.
