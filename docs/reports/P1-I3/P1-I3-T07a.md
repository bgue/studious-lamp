## Deviations
One deviation from the STEPS order, in `action_cancel`. The STEPS say: on a `CLIENT_ERRORS` failure, "say describe_error(exc) with error=True, call self.reload() and return". `reload()` on success calls `_fill`, which rewrites `#jobs-status` with the jobs summary, so the error text would be overwritten and never shown (the Allowed-paths rule says a client failure is shown on the status line). I call `self.reload()` first and then `self._say(describe_error(exc), error=True)`, the same "say last" order the success path already uses. No test covers this path, so the provided test file is unaffected. Flagging for the supervisor because it departs from the literal STEPS order.

## Learnings (proposed)
- The ticket's STEPS for `action_cancel` order the error before `reload()`, but `reload()` rewrites the status line on success. A STEPS line that orders a status message before a reload is wrong for every error path; the rule "say last" should apply to both branches. Candidate for `docs/memory/LEARNINGS.md` for the T07 family (T07b/c may have the same pattern).
- `AGENTS.md` points implementers at `docs/build-spec/01-tiers.md` §4 before the ticket's Context list. I read only the ticket's Context files, the report template, and the ticket, and did not open the build spec.
