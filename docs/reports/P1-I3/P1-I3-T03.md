## Open questions / Blocked
- Non-blocking, for the supervisor to decide: `_discover` includes `{exc}` in `ExtractorLoadError` (STEPS 2a). The brief says a plugin's exception text may hold a path or a value from the file, and that only the exception type goes into a message. An import-time error can contain a filesystem path. If the rule applies to load errors too, the message should be `extractor {entry.name!r} cannot be loaded: {type(exc).__name__}` and the chained `from exc` keeps the detail for developers. I did not change the STEPS text. The test is unaffected either way.
- Not in the STEPS, so not implemented: `contract_problem` does not compare `metadata.content_type` with the source's content type. The ticket lists only `sha256` and `size`.
