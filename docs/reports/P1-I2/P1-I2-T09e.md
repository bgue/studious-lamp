constructor `CreateTransmittal(actor=..., direction=direction, purpose=purpose, ...)`. With the
keyword form, `just check` fails pyright (`str` is not assignable to the `Direction` and `Purpose`
literals, because typer passes plain strings). The body builds the command with
`CreateTransmittal.model_validate({...})` instead, the same pattern the STEPS give for `answer`.

reaches `_service_errors` as `error: <field>: <message>`. The provided test
`test_create_refuses_what_the_module_refuses` (purpose check) passes.

comments removed; test file copied byte for byte (`cmp` identical to the provided `.py.txt`).

## Learnings (proposed)
- The STEPS for `create` name a keyword constructor for `CreateTransmittal`. Typer hands the command plain `str` values, and pyright in `standard` mode rejects them for the `Literal`-typed `direction` and `purpose` fields. The STEPS for `answer` already use `model_validate` for the same reason. Suggest the ticket template say `model_validate` for any command whose fields are literal types.
- `uv run pytest packages/tl-cli -q` takes about 10 minutes on SQLite, longer than the 600 s foreground limit of the shell tool. Run it in the background and poll the output file.
- The `ruff format` run on a file that was just edited is reported by the harness as "modified since last read"; it is harmless, re-read the file before the next edit.
