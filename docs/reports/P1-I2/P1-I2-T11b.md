## Learnings (proposed)
- `uv run pytest packages/tl-cli -q | tail -15` prints nothing until the run ends. The full tl-cli run took about 8.5 minutes, so the 120 s foreground limit moved it to the background. Writing the output to a file, or running it in the background from the start, avoids the wait.
- Another worktree's `pytest` was running against the same `tl_test` Postgres at the same time. No failures came from this, but the overlap is worth knowing when timing or cleanup looks odd.
- The ticket's Report requirement mentions "the decisive lines of the parity run", but no parity command is in Acceptance. I took it to mean the `--adapters sqlite,postgres` run above.
