## Learnings (proposed)
- The STEPS order uploads the file (`_upload`, which registers it in the slot) before `AttachRendition` or `ReplaceSignedRendition` can refuse it. So a refused `add` or `replace-signed` leaves an uploaded file in the slot that is not a rendition. The provided test only checks the `error:` text and the rendition listing, so it does not cover this. I did not inspect the file-service state after a refusal; this is from reading the STEPS order.
- `handle_attach_rendition` and `handle_replace_signed_rendition` are implemented in the tree (the ticket's excerpt shows `...`). The ticket's Context list did not mention the template, so I read `docs/templates/haiku-report.md` only to write this report.
