## Learnings (proposed)
- The ticket names the engineering sibling as `packages/tl-modules/engineering/src/tl_mod_engineering/import_/mapping.py` in Context. The real path is `tl_mod_engineering/imports/mapping.py` (no underscore). It was found with a directory listing; the ticket's path does not exist.
- The ticket says the test "compares [the messages] exactly". The provided test uses `pytest.raises(..., match=...)`, which is a regex `search`, not equality. Messages are matched as substrings or regexes, and the `r"the file lacks the column\(s\): NAME"` pattern shows the author expected that. An implementer following "exactly" literally could over-constrain the message.
- The pasted `model.py` in the ticket reads `import annotationsfrom dataclasses import ...`. That is a paste artifact; the file on disk is correct. Read the file, not the paste.
- Acceptance says "8 test functions pass (on SQLite and again on Postgres)". Pytest reports 19 cases, and the adapter option does not change that count for non-database tests. The "8" is the function count, not the case count.
- `pytest.raises(match=...)` in the test for the template error `columns.0.to` relies on the pydantic `loc` joined with dots. This works because the location is a list index, `str(part)` makes it `0`.
- Under the literal STEPS 2 check, a header with a trailing comma (two blank header cells) fails with `the file has a column twice: ` (an empty name). The message is misleading for that case; see the open question.

## Open questions / Blocked
Question for the supervisor (does not block acceptance; the implementation follows the ticket literally, and the provided tests pass):

Should a blank header cell count as a repeated column? STEPS 2 and the Specification say a header name that appears twice is `MappingError("the file has a column twice: " + ", ".join(sorted names))`. Read literally, two blank header cells (for example a trailing comma in a DMS export header) reject the whole file, and the message names an empty column. The attempt-1 implementation skipped blank names, which accepted such files; the reviewer ruled that a judgement call outside the ticket. Options: (a) keep the literal rule, so a file with a blank header cell repeated is rejected; (b) skip blank names in the duplicate check, as the sibling engineering mapping does (a change of the STEPS text, not covered by any provided test); (c) reject blank header cells with their own message. No test in the provided file covers this case. Decision needed before the import handles real DMS exports.
