## Deviations
1. `--project` is required (the shared `Project` option, as in `awp report`); the spec's `[--project P]` and "default project like
   `awp_report.py`" have no basis (that command has no default). A missing option is a usage error, exit 2.
2. **Viewer and the stored budget (open question 1).** `cur_awp_rollup` rows add every package, hidden ones included. When a viewer
   cannot open a CWP or IWP of the project, node and line budgets and percents are null (empty CSV cells) and the note `no budget
   rollup yet` shows besides `some packages not shown`. Spec (4) says budgets come from the stored rows; this leaves them out only
   for that viewer so no figure adds a hidden package.
3. A CWP with IWPs but no WBS allocation (or an allocation to no node) earns into no node or line (an escalation trigger). Nothing
   invented: the rollup adds the note `earned hours without a WBS allocation are not shown`. Allocation percents under 100 drop the rest.
4. `rollup.compute` rounds node totals half-to-even (not changed: not mine); CWP figures here are half-up (rule 3). They differ
   only on an exact `.x5` tie.
5. Import of the private `engine._weights` (rule 2 reuse); `ScopeItemRow` is built with `key=""`.
6. Size bound: `MAX_ROWS = 20000` lines, else `ExportError("export: too many rows")` (text added by me; the lines are bounded by cost codes).
   `export_progress` returns text, written by the `csv` module (`QUOTE_ALL`, `\n`); the CLI prints it whole.
7. `--out` replaces an existing file silently (mode forced to 0600), unlike `comm export`, which wants `--force`.
8. Cost code text is read from `cur_cost_costcode.code` (read only; the table name as a literal, no import of `tl_mod_cost`).
