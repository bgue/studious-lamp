## Learnings (proposed)
- The `show` output needs each commodity's `kind` (`<commodity>  <kind>  ...`), but the pasted interface `rules_for(key) -> Rules` returns only `by_commodity` steps. `Rules` has no `kind` field, so the ticket's interface does not supply the value its output format needs. The only in-repo source is the private `tl_mod_awp.progress.engine._package_doc(key)` (engine lines 163-178, inside the Context range), which returns the `PackageDoc` with `rules_of_credit[*].kind`.

## Open questions / Blocked
Blocked: where does `show` get `kind` per commodity?

The pasted interface gives no public way to read `kind`:
- `rules_for(key)` returns `Rules(edition, by_commodity)` with steps only.
- `_package_doc(key)` is private to `tl_mod_awp.progress.engine`. Importing it from `tl_cli` crosses a package boundary with a private name, and the ticket does not list it as an interface.
- Adding `kind` to `Rules` or exposing a public package-doc accessor needs an engine change, which is outside this ticket's Allowed paths.

Options for the supervisor:
1. Allow `awp_roc.py` to import `tl_mod_awp.progress.engine._package_doc` (private) and say so in the pasted interfaces.
2. Ask for a public accessor (for example `package_doc(key)` or `kind` on `CreditRule` in `Rules`) in a prior or new ticket, then re-run T01.
3. Have `awp_roc.py` load the package through `get_provider().registry().get(name, version)` itself, duplicating the lookup in `_package_doc`.

Secondary note, not blocking: the `source default|setting` line needs the stored value, which the pasted interface does not supply. `value_of(conn, EDITION_SETTING, project=project_of_scope(scope))` from `tl_core.settings.resolver` gives it. That is a public function, so I would use it unless told otherwise.
