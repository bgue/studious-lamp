## Learnings (proposed)
- Two test modules named `test_confidentiality_walk.py` (tl-api and tl-mcp) collide in one `just gate` session. Load one by path under a unique name.
- `tl_mcp.errors` forces the LOWEST viewer on every tool call, so MCP reads never differ by reader. The brief's MCP section ("as each reader") cannot be tested per class without a source change.
- A CLI test process may run with `TL_ENV=test`, which honours dev tokens. The lowest viewer must pass `TL_ENV: None` to CliRunner, or it reads as the dev owner.
- A missing-IWP answer repeats the number the caller sent, so a leak check on output must exempt numbers that appear in argv.
- `MCP_ACTIONS` entries are `mcp.<tool>`, not bare tool names.
