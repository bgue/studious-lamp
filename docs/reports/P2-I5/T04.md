## Helper change (progress_world.py)
- Before: `WeekWorld.issued(state)` created the IWP and called `self.w.set_status(iwp, state)`, a write to `cur_core_record.status` only. `cur_workflow_state` stayed `Draft`, so `look_ahead_view` (reads `iwp_list`, workflow state) printed `Draft` while `week_detail` printed `Issued`.
- After: `issued(state)` walks `IWP_PATH[state]` (a new dict in the same file) with the real transitions. `StartIwpDevelopment` and `SendIwpToConstraintCheck` are the awp commands; `ready`, `hold`, `issue`, `start`, `complete`, `close` run through `tl_mod_awp.common.move`, the same transition function the readiness engine uses (`tl_core.projection.workflow` writes `cur_core_record.status` and `cur_workflow_state` in one projection step). The comment above `IWP_PATH` says so.
- Why not IssueIwp/SignOffIwp: IssueIwp needs two sign-offs with distinct roles and a record hash; no command closes an IWP. The `common.move` path is cheaper and is the path `test_kpis.py` already uses (`KpiWeekWorld`).
- `On hold` (path ends with `hold` from Ready) is added; `test_week.py` needs it. `Split` and `Cancelled` are not reached.

## Learnings (proposed)
- A test helper that sets `cur_core_record.status` by hand leaves `cur_workflow_state` at `Draft`. Readers that use the workflow state (`iwp_list`, look-ahead) and readers that use the record status (`week_detail`) then disagree in the same world. Real use never does this; helpers should reach states through transitions.
