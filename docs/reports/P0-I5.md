A filtered delta subscription (`Workflow.Transitioned`, `* -> Issued`) receives one signed event out of three, the receiver verifies the signature; a replay of the whole `seq` range re-sends the same event id and the receiver flags it as a duplicate; a `410` goes to the dead-letter queue and a redrive delivers it; a secret rotation leaves a test event with two signatures and the `webhook-test: 1` header; no secret is in the ledger. The workflow events are appended directly because the driver needs no workflow definition; the Postgres half is `just test-parity`.

## Deviations from plan
- **No `Webhook.Delivered / Failed` ops events** (03 §8). Attempts, outcomes and health are operational `wh_*` rows; a `*` subscription would otherwise feed back on its own deliveries. A dead letter is a row; an auto-disable is a `WebhookSubscription.Disabled` event (B decision D4).
- **`data.detail`** (the ledger payload) is added to delta and full envelopes, and `datacontenttype` is `application/json` with no `@context` yet (D7).
- **Engine in `tl_core.webhooks`**, not `tl-api` (D1). New dependency `httpx` (BSD) in `tl-core` only.
- **Fan-out is a separate step** from the outbox projector: the outbox is one row per event, the dispatcher writes `wh_delivery` rows (D2). Fanout contract C1 to C3 held: `handles_all`, the Postgres unit of work running the registry like SQLite's, DDL from the generator.
- **`SqliteUowFactory`** is the trunk's canonical file from P0-I4 workstream C, copied verbatim; `tl_adapters.db.make_uow_factory(target)` returns it or `PostgresUowFactory`.
- **Unplanned but needed:** `WebhookStateTables` (a projector with no events so `create_schema` makes the `wh_*` tables and a rebuild never clears them), `active_windows` on subscriptions, `current_version` (the stream version inside the transaction), `tl webhook run`, `send_test` with the `webhook-test` header, and `extraPaths` for pyright in the root `pyproject.toml`.
