## Outcome
Objective met: yes. The correspondence module has its second and third domains.

- **Technical / RFI** (`correspondence.TechnicalItem`; RFI, technical query, deviation; numbers `P123-RFI-0001`). Anyone raises, edits, submits and answers; a document controller issues and escalates. The answer states its cost and schedule impact; a review sends it round again (`ReviewTechnical`, `ReissueTechnical`). The issue renders the letter PDF, records a stub send and starts the "answer required" clock; the answer meets it. `tl rfi`, the RFI log report (response days, on time, overdue, impact flags) and the constraint hook (a stub sink, D11).
- **Commercial** (`correspondence.CommercialItem`; early warning, change notice, site instruction, quotation, claim notice, detailed claim, payment application, back charge; numbers `P123-EW-0001`). Every command is a controller's and the items are restricted by default. Money is exact (two-place decimal text), each currency has its own total, never added. **Time bars**: a clock of kind `time_bar` from the day the raiser became aware, the clause's length when a clause is cited; issuing meets the bar, a day after it shows LATE. `tl comm`, the Commercial register report, the cost-system CSV export (private file, formulas quoted, class named).
- **Escalation.** `EscalateTechnical` turns an answered RFI into a Draft restricted early warning linked `derived from` the RFI, with its time bar counted from the answer. It writes nothing on the RFI stream. A controller runs it (`tl rfi escalate`), or the shipped rule `dev/seed/rules/rfi-escalation.json` proposes it when an RFI is answered (propose mode only) and a controller accepts the proposal (see Rule below).
- **Rule and thread target (T05, T05b).** The rule runs on the P1-I7 engine as `svc:rule-rfi-escalation`; a proposal waits in the review queue for a person with the controller access, and the command runs as that person with the source `rule:rfi-escalation`. `/raise rfi <title>` in a record thread plans a real `RaiseTechnical` (the module's target replaces the core placeholder).
- **Evidence trail.** `tl evidence`, `GET .../correspondence/{number}/evidence`, MCP `get_evidence_trail`: the linked records of an item as they stood at the end of any past day, replayed from the ledger, filtered by the viewer, bounded (depth 3, 200 nodes, 1000 links, 5000 events).
- **Feed.** `Correspondence.Issued`, `Technical.Answered` and `Commercial.Assessed` make cards by the domain file's policy (full, minimal or none); cards are tagged with their record so a reader sees only cards of records they may read.
- **Entry points.** CLI `tl rfi`, `tl comm`, `tl evidence`; API reads and the 19 new commands (47 in all, 24 of them controller acts); MCP read tools `list_rfis`, `get_rfi`, `list_commercial_items`, `get_commercial_item`, `get_evidence_trail`; the TUI screen on **Ctrl+G** (1 RFI log, 2 Commercial register, 3 evidence by day); the simulator's `rfi_author` and `client_rep` actors and the scenario `rfi-weeks`.

Demo path verified: `just demo P1-I6` passes its nine clauses on SQLite and on Postgres (see Showcase). A fresh clone was not tested; the demo and the gates ran on the `p1/i6` worktree.

## Security review
Two fresh-context security reviews of the supervisor's pieces. The first (changes requested) found eight classes (F1 to F8, fixed in eb31ba2); the re-check passed with four residuals (fixed in 32c7ed6). Each fix has a test that fails without it.

| Area | Fix |
|---|---|
| Commercial access (F1) | Every command that changes a Commercial item or its clocks needs a controller viewer whatever its access word: the Commercial commands, the generic link, file and property-set commands (`controller_only` guards), the clock commands (`require_controller_for`), cancelling a time bar (`require_controller_for_bar`) |
| Feed (F2) | Cards of a confidential stream are tagged with the record (`subjects_of`, `confidential_stream_types`); only `Correspondence.Issued`, `Technical.Answered` and `Commercial.Assessed` carry a policy; file events of a hidden record are tagged through `cur_files`; the walk compares each reader's scan cards with the records they may read |
| Answers (F3) | An answering item or revision must be readable by every reader of the RFI; otherwise the unknown-record message |
| Trail (F4) | The neighbour query has a LIMIT and a stop flag |
| Export (F5, F6) | The file is written 0600 with `O_NOFOLLOW`, `fchmod`, and refuses to replace a file without `--force`; the fetch is limit+1 with its own `export_too_large` error; the hint to name a class appears only for exportable classes |
| Time bars (F7, F8) | The issue day is floored at the awareness day; the single-controller limit is documented |

## Deviations from plan
- **The demo differs from the plan's eight clauses.** The planned feed-card clause (full and minimal cards) and the PDF rendition are covered by tests, not by the demo. Clause 3 is the rule's proposal, a user refused and a controller accepting it. The demo gained two clauses: the TUI and an agent read the same RFIs (8), and the simulator plays RFIs (9).
- **T05 was built in a second pass, after P1-I7 landed.** The rule is propose-only by design: acted by a rule the command is refused (a service actor reads as the lowest viewer and the command needs a controller viewer). The rule proposes for every answered RFI because a rule's `when` and `condition` cannot read the answer's domain data; `require_impact` makes the command refuse, when a person accepts it, an answer without a `yes` to cost or schedule impact. A restricted or privileged RFI never fires the rule (ADR-0017 section 7e, stated in ADR-0019 section 5): a controller escalates it by hand.
- **T10 was built by the supervisor,** not as a ticket. Simulated people hold role `user` only, so there is no commercial manager actor and the operator (a controller) issues the RFIs; `sim assert` excuses `correspondence.*` records written by operators.
- **A core change.** `tl_core/numbering/allocator.py` spells `{project}` without symbols (see Security review).
- **TUI key.** The screen is on Ctrl+G; F12, F5, Ctrl+R and Ctrl+E were taken.
- **Decisions during the build:** D13 (the reason on an update in review is advisory) and D14 (`expected_version=0` is treated as not given, as in 19 older sites; a module-wide change to `is not None` is a follow-up for the orchestrator).
