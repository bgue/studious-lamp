## Learnings (proposed)
- The STEPS for `commercial_lines` step 6 wraps the f-string across two lines (`f"` then `{clock_line(c)}"`). Read literally, the wrap could hide the leading space. The two spaces the ticket names match `item_lines` in `correspondence_text.py`, and the test pins the exact string, so I used `f"  {clock_line(c)}"`.
- The `CommercialView` interface is abridged, and the fields it inherits from `ItemView` (`number`, `state`, `subtype`, `subject`, `confidentiality`, `issued_on`, `clocks`) are not in the ticket. The Context list excludes `views.py`, so I did not read it. Pyright (0 errors) confirmed the names. A ticket that abridges an interface could say which fields are inherited.
- The full `packages/tl-tui` suite takes about 7 minutes on this machine (424 s). The ticket's Acceptance command needs a shell timeout of at least 600000 ms.
- L-P1-I6-1 did not apply: no boolean local was computed from an optional attribute. `if view.assessment_status:` narrows the `str | None` for `.replace` directly, and pyright accepted it.

## STEPS read as written (unclear points)
- `commercial_lines` step 5 says "only when `view.assessment_note` is set" and then "(one line)". I read it as: the note is appended to the same `assessment (...)` line, as the test expects (`... agreed USD 9000.00 (as stated)`).
- "Is set" is read as truthiness, so an empty string counts as not set. This matches the `or` idioms in the same steps. No test covers an empty string.
