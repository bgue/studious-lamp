## Learnings (proposed)
- A STEPS comment that wraps a quoted f-string at a line break does not say how the two lines join. In `rfi_lines` step 1 the header `f"{view.number}  {view.state}` / `{view.subtype or '-'}  class ...` looks like one space between state and subtype, but the provided test (and the other `  ` separators in the same step) need two. Read the test before choosing the join; the test wins.
- The fake's `open` count (`tests/fakes_correspondence.py`, `list_rfis`) counts every line whose state is not Closed or Void, so the answered RFI 0001 is counted as open and the seeded log shows `open 3`. The `RfiLog.open` docstring says "not answered, and neither Closed nor Void", which for the seed would give `open 2`. The provided test pins `open 3`. I display `log.open` as given, as the ticket says, and did not change the fake. See Open questions.

## Open questions / Blocked
- Open question for the supervisor (not blocking): `RfiLog.open` is documented as "not answered, and neither Closed nor Void" but the fake's `list_rfis` computes it as "not Closed and not Void" (answered items included), and `test_the_summary_counts_and_names_the_filters_that_are_on` expects `open 3` from that. Which definition is right is a decision for the owner of the report and the fake; this ticket only displays the figure.
