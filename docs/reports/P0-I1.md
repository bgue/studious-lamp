## Follow-ups filed
- Increment 5 (Postgres parity): binding of `psets_json` (a string into JSONB) and ISO strings into TIMESTAMPTZ is unverified; the generated Postgres DDL is golden-tested but never executed. Parity tests for the ledger, `append_in`, and the projector must run on both dialects.
- Increment 3: numbering (CLI and `CreateRecord` still require `--key`); `idempotency_key` is accepted and ignored; `Record.Corrected` has a projector but no command or CLI subcommand; no `tl record update` subcommand although `UpdateRecord` exists.
- A hash-chain verification command (`tl ledger verify`) is not built; the chain is written and tested but nothing audits it end to end.
- `tl events tail` pages through the whole scope to find the last N events; add a ledger method for reading the tail if scopes grow large.
- `tl projections rebuild` holds the SQLite write lock for the whole replay; the shadow rebuild of §24.2 belongs to Increment 7.
- The bus is in-process only and process-wide publishers live for the process; the out-of-process change feed (cursor reads, LISTEN/NOTIFY) arrives with the API increment.
- Ticket authors: list the required payload keys of seed events in tickets (T11 learning).
