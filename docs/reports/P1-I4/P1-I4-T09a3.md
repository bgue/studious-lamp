## Deviations
none outside scope. Within the STEPS (the three functions) three lines were done slightly differently; each is listed below with its reason.

- `_fill`: an early `if page is None: return` guard is not in the STEPS. Reason: `self.page` is `ActivityPage | None` and pyright strict needs the narrowing before `page.rows` and `page.snapshot_key`. The guard does not change behaviour, since `_fill` is only called after a successful read.
- `_describe`: the STEPS say to append the empty line and then read the trend in the second `try`. The implementation reads the trend first and appends the empty line after the read succeeds, and appends it in the `except` branch too. The panel text is the same in both orders.
- `_describe` and `reload`: the STEPS say to write the error to the panel and status line. The status line is written with `self._say(..., error=True)`, which is the existing helper that prefixes `! `. The same format is used everywhere else in the screen.

Imports: no import became unused after the STEPS were filled in, so none was removed. Ruff (F401 enforced after the `noqa` header was removed) and pyright both pass.

## Learnings (proposed)
- The stub's "remove the imports that are then unused" step turned out to be a no-op here: every import in the stub is used by the three bodies. A ticket can say "remove if unused" without implying that some will be.
- `uv sync --all-packages` prints a `UV_NATIVE_TLS` deprecation warning on every `uv run`. It is noise, not a failure.
- The full `packages/tl-tui` suite takes about 8 minutes in this worktree (912 tests). The ticket's acceptance is only the one file, but the full package run is a useful regression check when a widget is shared with a parent screen.
