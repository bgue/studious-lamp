## STEPS lines done differently
- STEPS 5–6 (row output): rows are built as one list of strings per `LIST_FIELDS` name from the typed attributes (`c.added`, `c.float_changes`, ...), and the cut line is `c.totals.get(name, 0) - len(rows[name])`. Same lines, same order; reason: keeps every row's format next to its field name and avoids an untyped `getattr` loop under pyright strict.
- Row format of `critical` and `duration` (not specified by STEPS): `days()` is used for both values, as for `float`. The docstring says `<old>d`; for a `None` value the output is `-`. Reason: `days()` is the only float formatter the ticket provides.
- `look_ahead` wraps the view call in `try`/`except ValueError` inside the `with` and calls `fail(str(problem))`, as STEPS 2 says; `r` is bound only after the `with`, which pyright accepts because `fail` is `NoReturn`.

## Learnings (proposed)
- `just check` runs `ruff format --check .` before pyright and the codegen and licence checks, so one unformatted line stops the chain at line 18 and hides any later failure. Run `uv run ruff format <your file>` before `just check` when you wrap calls by hand; a three-line call that fits in 100 columns gets joined.
- Timings on this machine: the compare file on SQLite takes about 77–85 s (12 tests, roughly 6–7 s each); on both adapters 24 tests take about 308 s, so the 120 s shell default is not enough for either run. This matches L-P1-I4-9.
