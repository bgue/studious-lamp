## Learnings (proposed)
- `registry.list_packages` defaults to `scope=None` (all scopes). Project-kind packages (`project:<id>`, e.g. `schema/fixtures/prj.P123@1.0.0.yaml`) are published by the same handler, so they are exported too unless a scope is passed.
- `list_packages` silently caps each state at `MAX_PAGE` (1000) rows; an export beyond that would be partial with no message.
- The provided test does not cover a `--package` filter that matches a package with several versions in two scopes.
