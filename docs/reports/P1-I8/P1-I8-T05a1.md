## Learnings (proposed)
- `tl_schema.classify.ChangeClass` and `tl_mod_schemareg.impact_types.Section` are `typing.Literal` string unions, not `Enum`s. An f-string prints the bare value (`additive`, `views`), so `f"{change.cls}"` is correct without `.value`. The ticket does not say this and a reader might reach for `.value`, which raises `AttributeError`.
- `tl_cli.derive_support.cell(value, width=40)` cuts at `width` and appends `…`. For identifiers that must not be shortened (the base `name@version`), pass a wider width. `cell(0)` returns `0`, so it is safe for counts.
- The provided test file on both adapters takes about three minutes (`194.75s`) because each case builds a fresh database; plan for it.

## Open questions / Blocked
none blocking. Two questions for the supervisor:
1. `diff` follows STEPS step 3 and the docstring literally: once `analyse` has run, an empty diff prints `no base to compare with (first version)`. That also happens for an analysed version that has a base but no differences from it (identical content), where the message is misleading. The spec says "After it, an empty diff means a first version", so I implemented exactly that. Should an identical-content version print a different line (for example `no differences from <base>`)? I have not changed it, since that would be a new output line the ticket does not name.
2. `classify` prints the base with `cell(report.base, 200)` rather than the default width 40, so a long package name is not cut. The ticket says "Use cell() for a value that may be None" and does not give a width. I took this as within the STEPS; say if the default is wanted.
