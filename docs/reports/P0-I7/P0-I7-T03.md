## Learnings (proposed)
- `summary` is assigned inside the `try` block that ends in `_fail(...)` (a `NoReturn` helper). pyright accepts this without the `if not issues else None` pattern the ticket suggests. In `verify`, the divergence printing and `raise typer.Exit(code=1)` sit inside the same `try`, so `typer.Exit` passes through `except ArchiveError` and the `finally` still disposes the engine.
- `FsArchiveStore(archive)` creates its directory, so the `is_dir()` check in `verify` must come before constructing it, as the ticket states. The seal path's `_target` and `_signer` checks run before the store is built, which is why a failed seal leaves no archive directory behind (the test asserts this).
