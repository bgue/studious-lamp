## Learnings (proposed)
- `just check` does not lint or link-check Markdown, so the acceptance for doc-only tickets only proves the build is unchanged. A doc-only ticket that changes a tool surface can leave other runbooks stale without any gate noticing. A cheap check (for example, a grep for tool names across `docs/runbooks/`) belongs in the ticket's acceptance.
- The `uv` commands print a `UV_NATIVE_TLS is deprecated` warning on every call in this environment. It is noise, not a failure.
- The ticket's *Context* list named only four files, but the step-4 tool list in `api-and-mcp-dev.md` is affected by any new MCP tool. The supervisor may want the ticket template to list "other runbooks that enumerate the tool surface" in context.
