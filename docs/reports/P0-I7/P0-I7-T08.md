## Learnings (proposed)
- The runbook's fenced command blocks sit inside numbered lists and are indented by three spaces. A search for fences that starts at column 0 (`^```` in grep or awk) finds none. Use a pattern that allows leading whitespace when checking runbooks.
- `just check` does not lint Markdown. The runbook passes it without any Markdown check, so the Facts-match check above is the only check on the command text.
- The restore facts copy a snapshot over `dev/data/tl.db` for a WAL-mode ledger. The Facts do not mention the `-wal` and `-shm` sidecar files. See Open questions.

## Open questions / Blocked
none blocking. The ticket's escalation trigger (facts contradict each other, or a step needs a command that is not listed) did not occur. The following points are open questions for the supervisor.

1. **Sidecar files on snapshot restore.** The restore step copies `tl-snap.db` over `dev/data/tl.db`. The ledger is in WAL mode, so a `dev/data/tl.db-wal` or `-shm` file from the old ledger may still exist. The Facts give no step for them. SQLite could apply an old WAL to the restored file. I did not add a remove command, because none is listed. The runbook only says to stop anything that writes to the ledger. Please decide the step.
2. **Hash re-check.** The snapshot prints a sha256, but no listed command recomputes it. The runbook says to record the hash and does not give a check step.
3. **Restored replica to ledger.** The Facts give a copy-into-place step only for snapshots. The runbook restores the replica to `dev/data/restored.db` and verifies it, and it does not say how to make it the live ledger.
4. **Delete command.** Fact 7 says to "delete it" for a snapshot or restored file. No delete command is listed. The runbook says to delete the file by hand.
5. **Verify output shape.** The Facts give the exact output only for `uv run tl ledger verify` on `dev/data/tl.db`. For `uv run tl ledger verify --db dev/data/restored.db` the runbook expects a line starting with `verified ledger dev/data/restored.db`. That shape is assumed from the other output.
6. **Rolling back a snapshot restore.** Fact 7 covers only new files. It does not say how to get back to the previous `dev/data/tl.db` after a snapshot has been copied over it. The runbook says only that events after the snapshot are lost.
7. **Related runbooks not on this branch.** `ledger-archive-and-verify.md`, `restore-from-archive.md` and `pgbackrest-restore.md` are the outputs of tickets T05 to T07. They are not in `docs/runbooks/` on this branch yet. The links will resolve only after those tickets merge.
8. **Business-hours line.** The Facts say a snapshot is taken while the ledger is in use. They say nothing about restores or replication under load. The runbook says snapshots are safe during business hours and restores need the writer stopped, which is my reading.
