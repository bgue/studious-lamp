## Learnings (proposed)
- Token expiry in `ls`: `accounts.issue_agent_token` stores `expires_at` with microseconds (`iso_z`, e.g. `2026-10-11T03:14:07.000000Z`). The ticket's STEPS compare that to a second-precision `now` string (`%Y-%m-%dT%H:%M:%SZ`). Within the last second before expiry, a token is therefore shown as `expired` slightly early. Implemented as specified; a parsed-datetime comparison would be exact. The supervisor decides.
- A STEPS comment and the pasted signature cannot tell an explicit `--days 90` from the default, so `--days 90 --no-expiry` is accepted silently (see Open questions).
- The provided fixtures call `tl admin user add` in setup, so every token test errors at setup until the user command is filled. A stub failure looks like a fixture error, not a test failure.
