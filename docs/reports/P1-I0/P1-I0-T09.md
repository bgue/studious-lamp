## Learnings (proposed)
- The full `packages/tl-tui` pytest run takes about 4.5 minutes (668 tests), longer than the 120 s foreground limit of the shell tool. Run it in the background with its output written to a file, then read the file.
- Several worktrees run tests at the same time on this machine, and all of them use `TL_PG_URL=postgresql://postgres:postgres@localhost:5432/tl_test`. While this ticket ran, a `pytest packages/tl-tui` from `p1-i0-t08` was running in parallel. No failure was seen, but concurrent runs may share one test database; a per-worktree database name would remove the risk.
- The ticket's STEPS for `_stamp` (`strftime("%Y-%m-%dT%H:%M:%S.000000Z")`) always write zero microseconds, so "now" is truncated to the second (see Open questions).
- The provided test expects the grammatically odd `"... is a agent account."`; the STEPS text `is a {view.kind} account` produces it, so the wording is pinned by the test, not a typo to fix.

## Open questions / Blocked
- `_stamp()`: I followed the STEPS literally, so it writes `.000000` microseconds. The ticket text says "with microseconds". A token expiring at `12:00:00.300` would show as `✓ active` at `12:00:00.700` and `! expired` only from `12:00:01`. Using `self.now().strftime("%Y-%m-%dT%H:%M:%S.%fZ")` would keep the real microseconds and still compare correctly as text with the stored stamps. Nothing in the provided tests distinguishes the two, because the fixed clock is `12:00:00` exactly. Supervisor to decide; I did not change it.
