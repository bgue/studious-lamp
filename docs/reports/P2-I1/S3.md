## Open questions
1. Record keys are unique per project across record types (`cur_core_record` scope+key). A WBS code, a CWA code and a cost-code key cannot be equal (a GC node `1` and a cost code `1` collide). The handlers refuse with a fixed message; T02 (loaders) will meet it. Needs a decision: namespaced keys, or accept.
2. `MapWbsToCostCodes` takes 1 to 20 lines (the literal spec), so an allocation cannot be cleared. Allow an empty list?
3. A rollup requested while the job is `running` is not queued; S5's settle must re-check the ledger head and queue again.
4. `AwpError` classes have no `tl_api.errors` mapping yet (glue); `AWP_COMMANDS` is not yet in `tl_api.commands.COMMANDS`.
5. `reason_code` is checked by shape, not against the `PathReason` code list (the list lives in the ledger; not in the S3 rules).
6. `APPROVALS` schema paths for the orchestrator: `schema/modules/awp/wbs.yaml`, `schema/modules/awp/cwa.yaml`, `schema/modules/awp/external_package.yaml`.

## Candidate learnings
- A module's `ModuleSpec.generic_commands` entry of `frozenset()` is what makes a link from its record unretractable by a person; core refuses before the rule-source check.
- `create_module_record` keys share one namespace per project across all record types.
- Moving a WBS node renumbers siblings with `WBSNode.Revised` events of their own, so the projection never holds gaps.
