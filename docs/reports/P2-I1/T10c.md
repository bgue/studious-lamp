## Pins (consequential)
- `allocated` and the counts use the record `voided` flag (the CWP state Void is the voided flag, `common.py`). An allocation to a voided or hidden node is left out, as in `cwp_detail.allocations`.
- A hidden CWP leaves `cwp_list` through the SQL `not_hidden` clause. Under a patched `_hidden` it stays listed with `allocated` False; its allocations, names and counts drop.
- `cwp_count` walks the `parent_id` chain over all WBS nodes of the scope. A hidden or voided node still links its children to their parents, but it contributes no allocation. The count is distinct CWP ids.
- A leaf is a node that is no node's `parent_id`. Only a leaf's `wbs_detail` fills `cwps`, sorted by number; `wbs_tree` and parents give `[]`.
- `WbsCwp.hours` = `budget_hours * percent / 100`, quantized to 0.01 with ROUND_HALF_EVEN; None without a budget.
- `PackageRow.cwps`: distinct, sorted numbers of non-voided CWPs with a non-retracted `requires` link to the package. `cwp_detail.packages` gets the same values.
- Queries: `cwp_list` +1 allocation query and +2 `_hidden` checks per call; `wbs_tree` and `wbs_detail` +1 node-chain query each; `package_list` +1 link query and +1 `_hidden` check. None per row.

## Learnings (proposed)
- Ticket statements about seed contents were not checked against the seed. The S4 seed has no unallocated CWP; read the seed table before relying on a parenthetical.
- A patched `views._hidden` removes a CWP's allocations and its names in package and WBS reads, but not its row in `cwp_list`, which the SQL `not_hidden` clause decides. Checks for a patched `_hidden` should assert the allocation and name effects.
- `AllocateCwpToWbs` and `CreateCwp` take the record id as `cwp` (the S4 pattern); `AllocateCwpToWbs` replaces the whole allocation.
