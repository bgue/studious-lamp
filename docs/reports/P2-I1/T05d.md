## tui-layout checklist (skill `tui-layout`)
1. Glance: breadcrumb `P123 › CWPs › number: subject`, filter, list with State, keys row; the panel names the CWP and its state.
2. Identity line first in the panel; every other panel value is a labelled line or the one summary line; no stray values.
3. Sections come from `awp_text.cwp_page` (Scope, Allocation, References, Schedule, Timeline, Files and links), one blank line apart.
4. Tiers: the panel uses `cwp_page(panel=True, technical=mode_of(app).technical)`; no extended properties on the panel. Technical mode was not exercised in the acceptance run.
5. Columns: Number, Subject, State first; `Discipline` and `Planned start` drop first at 80; no constant columns in the seed; no sideways scroll at 170.
6. Panel: summary line under the state; repeated `Budget hours 40 h` vs summary `40 h` is the T05a design (the summary repeats facts by rule); Timeline is a 4-column table.

## Learnings (proposed)
- `app.screen` raises `ScreenStackError` after `app.run_test` exits: acceptance checks must read widget text inside the pilot scenario (the first draft did not).
- `awp_text` has no list-level summary and no right-alignment hook for `CWP_RIGHT`; `LogScreen` offers no per-column alignment, so `Budget h` is left-aligned in the register. A supervisor may want a hook.
- The ticket's Interfaces say `action_*` call `self._fill()`; the filters need the held rows recomputed first, so the screen calls `_apply()` (sets `self.rows`, then `_fill`).
