## Learnings (proposed)
- F6 and F7 are used with two meanings. The ticket and D62 in `docs/tickets/P2-I1/STATE.md` mean "rename on reload" (F6) and "CWA reload" (F7). The S7 report's own F6 means "a reinstated node keeps its old title on reload". The same thing, numbered differently. Use the D62 numbers in new docs.
- `ReinstateWbsNode` / `WBSNode.Reinstated` (D58) are not in `docs/build-spec/specs/m3-wbs-cwp.md` §3 or §2 (the spec predates S7). The CLI has no reinstate verb; the only route is `POST /commands/ReinstateWbsNode`.
- The `tl awp report`, `rollup` and `worker` groups print no subcommand list in `--help`; check them with their own `--help`.

## Open questions / Blocked

2. Access words: `schema/settings/access-words.yaml` gives `awp.wbs.configure`, `awp.path.configure`, `awp.cwp.release`, `awp.cwp.close` and `awp.void` the table word `controller`; spec §3 says "superuser" for the same words. The docs give the fine word only and do not name a role.
3. `tl awp worker` has no access word in the tree; the docs say nothing about one. Confirm whether it needs one.
4. The spec §3 table lacks the `ReinstateWbsNode` row and the `RequestRollup` note; left as is (spec is not in Allowed paths).

## Orchestrator decision (2026-11-05, after review)

(`mcp.list_cwps` ...), and each read tool also passes the `document.read` guard under the agent's viewer
(`awp_tools.py` docstring, `guarded`). The orchestrator rewrote the README line to say both. Questions 2 and 3
(spec §3 role wording, no access word for `tl awp worker`) are follow-ups for the P2-I1 report, not blockers.
