Status: done, awaiting schema approval at merge (P2-Q10). No tests written (owner policy: tests at C3, T11).

## Deviations (first)
1. `feed_policy: none` is declared as a required payload field with `equals_string: none` on the eight no-card
   events (the shape the correspondence events use). Core `tl_core/feed/cards.py` honours the key only for
   `POLICY_EVENT_TYPES` (three correspondence events), so the awp events still make cards until that set
   names them. That is a `tl_core` change outside this piece: see Open question.
2. The `expected_links` expectation at Released is declared as `tl:expects_link` on `awp.CWP` (the place
   `tl_core.links.expected` reads it), and the workflow carries no `expected_links` guard, because a guard
   fails the move when a link is missing and the spec says "never blocking".
3. LinkML has no `maxlength`; the length limits (200, 120, 40) are `pattern: "^.{0,N}$"`.
4. Added `last_seq` to every typed table (cost-module convention) and a `row_id` identifier on child and
   rollup tables. `budget_hours`, `percent` and rollup `value` are text columns (decimals are text per spec).
5. `ExternalPackage` is an abstract base (no table) shared by `EWPRef` and `PWPRef`; each has its own table.
6. Code values of `Commodity` and `PathReason` are slugs (`structural-steel`, `civil-earthworks`,
   `mechanical-equipment`, `Owner-request`); labels carry the spec words. The nine values and their order are
   as the brief lists them.
7. `WBSNode.BudgetRolledUp.by_cost_code` carries the unallocated hours as a line whose `cost_code_id` is null.
