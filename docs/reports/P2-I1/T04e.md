## Learnings (proposed)
- `worker --once --requeue` after a `rollup` request still runs the requested job: the queued row is not an orphan, so `requeued 0` is printed first and then the job runs. The ticket's `PASS requeue` only checks the first line, which is what the script does.
- `views.wbs_tree(conn, scope)` takes a SQLAlchemy connection (`open_uow(target)` then `uow.conn()`); its `total_hours` is None until a worker run has written the rollup rows.
- The ruff limit is 100 columns and isort wants the parenthesized multi-line form for the `tl_cli.derive_support` import; a one-line import of its seven names fails `just check`.
