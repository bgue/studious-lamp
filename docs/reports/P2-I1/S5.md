## Decisions
- A node with no stored row and an all-zero figure is not written (no row means no budget). A node that had a figure and goes to zero gets an event. This keeps a 5 000-node tree from writing 5 000 zero events.
- Only leaves take CWP hours (spec); hours allocated to a non-leaf node are ignored. Parents sum children exactly, round once.
- Changed nodes are taken in id (ULID) order, the first 500 per run; the rest wait for the re-queue. A parent can be written before its children in one run (the next run fixes it).
- D-c: `rollup.requeue_if_moved` (settle, after `queue.complete`) looks for `WBSNode.{Revised,Retired,CostCodesMapped}`, `CWP.{Revised,AllocatedToWbs}` or `Record.Voided` on an `awp.CWP` stream after `as_of_seq` in the scope; `request()` signature unchanged. `remaining > 0` always re-queues.
- `worker.requeue_orphans(target)` queues each project whose figure-changing events passed its last `as_of_seq` (after a restore). A project that rolled up to all zeros has no row, so it is queued again each call; harmless.
- Actor `svc:awp.rollup`; job kind writes no job-record events (`started`, `failed`, `expired` are no-ops; the queue row holds the error).

## Learnings (proposed)
- `DefineWbsNode` does not call `rollup.request()`; only map, move and retire do. A script that seeds nodes and CWPs by other means must request a run itself.
- `RunResult.outcome` is `done`/`lost`/`retry`/`final`; `run_once()` returns `None` when nothing is claimable.
- A `Midway` subclass of the kind (run calls commands) is a cheap way to test "request while running" without threads.
