# Phase 0 audit: brief §16 against the code

Purpose: one row per Phase 0 bullet and per exit clause of brief §16, with the status the code supports, the evidence a reviewer can run or open, and the gap that remains. Written 2026-10-11 by the P0-I8 workstream E supervisor from the code on `p0/i8e` (the trunk, P0-I1 to P0-I7, and P0-I8 workstreams A and C), not only from the increment reports. Rows that depend on workstream B (extension types) or D (performance) say so and are completed after those merge (see *Pending merges* at the end).

Status words: **done** (the bullet is met and exercised), **partial** (met in part, the gap is named), **deviation** (met by a different means, decided and recorded), **deferred-to-human** (blocked on a human gate in `docs/build-spec/04-gates.md` §2).

Evidence paths are relative to the repository root. "Demo" means `just demo <id>`; "parity" means `just test-parity` (SQLite and Postgres).

## 5. Counts and reading guide

Of the 16 bullets of §16 (bullet 3 split into seven rows, 22 rows in all): done 15, partial 4 (bullets 2, 8, 10, 11), deviation 3 (comments, attachments, simulator through MCP), deferred-to-human 0 as a whole row. Human gates sit inside "done" rows as named gaps and are collected in `docs/reports/PHASE-0.md` §6(a). The four exit clauses are done; the demo is the evidence.

The largest honest gaps, in order of what a product owner would care about:
1. The server, TUI and operator commands run on SQLite only; Postgres is proven by the parity suite and the restore, not by a running service.
2. Upgrade tooling (shadow rebuild, compatibility matrix, migration) does not exist.
3. No real authentication or permission model; every authenticated actor may do everything except what the fixed agent rules refuse.
4. The CI workflow has never run on a runner.
5. MinIO has never run; secrets (`wh_secret`, archive key) are dev-grade.
