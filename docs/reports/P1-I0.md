## Outcome
Objective met: yes. Every FANOUT exit clause is met and shown by the demo.
- Real sign-in replaces the ADR-0005 dev stub in the library, API, CLI, TUI and MCP: accounts, two roles (`admin`, `user`), 12-hour sessions, a flat per-name lockout and a per-source limiter, admin-issued agent tokens (`TL_AGENT_TOKEN`, re-checked on every MCP call), an identity seam (`IdentityProvider`) that Entra ID can replace, and the seeded `demo`/`demo` admin for dev and demo setups only.
- The API server, the embedded TUI, the MCP server, the simulator and every `tl` command group take a SQLite path or a `postgresql://` URL from `--db` / `TL_DB`, through one factory (`tl_adapters.backend.open_backend`); a test pins that no entry point imports the SQLite adapter. On a Postgres ledger the CLI always needs a session, and `tl sim` needs a signed-in admin.
- Secrets never enter the ledger, archive, lake or webhooks; account events are hidden from feeds, webhooks and default subscriptions and redacted in the lake.

Demo path verified from the repository root: yes, `just demo P1-I0` (about 3 minutes per backend) passes on SQLite and on Postgres. Output, one `PASS` line per clause on each backend:

## Follow-ups filed
- LISTEN/NOTIFY (`NotifyListener`) is not wired into the API feed or the embedded feed: a write from another process arrives by the 0.25 s poll on both databases. Wiring it would cut that to about 50 ms at the cost of a connection and a polling thread per process.
- The API's Postgres pool (5 connections plus 5 overflow) is unmeasured under load; the Phase 0 benches ran the library, not the server.
- `tl migrate` (SQLite to Postgres) is still the human-gated P0-I5-T99; the supported route is `tl archive seal` and `tl restore --from-archive`.
- A front-door rate limiter (reverse proxy, gateway or WAF) on `/auth/sign-in` and `/auth/password` is a release gate (ADR-0009 section 15); the in-process limiter is a second layer, per process and in memory.
- LOW-B of the re-review: `application_name` is shown in clear in `display_target` by design (it is a label, not a secret); nothing to change unless a deployment puts a secret there.
- `query_db` and `render_screen` of the dev MCP server stay SQLite only (decision C4).
- Not built, by decision: Entra ID, per-record permissions, password change in the TUI.
