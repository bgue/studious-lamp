## Learnings (proposed)
- A dev ledger file with no session reads as the file owner (`session_viewer`), which holds the restricted level. Any test
  of hidden items for a named person must sign in as that person; `--actor` alone does not change the viewer.
- `_execute` in `awp_write` is bound to `AWP_COMMANDS`. Any new command table needs its own gate-and-run helper, not a reuse.

## Open questions / Blocked
- Blocked: the ticket's test "an actor without `quality.view` is refused before any SELECT" cannot be set up. `World.person(name, ())`
  raises `InvalidAccountError: an account needs at least one role`. Platform roles are admin, document_controller and user, and
  `user` holds `quality.view` (read). A dev-file `--actor` with no account is also not refused (the dev-ledger rule holds `user`
  everywhere). Question for the supervisor: which account or fixture gives an actor with no quality read word? The test is left
  out, not weakened. Nothing else is blocked.
