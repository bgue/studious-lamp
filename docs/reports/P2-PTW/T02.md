## Design notes
- Hidden filter: isolation hidden via its own record (`not_hidden("r.id")`) and its point record (`i.point_record_id IS NULL OR not_hidden_each(...)`); gas test via its own record and its permit record `pr.id` (a permit for a restricted record is hidden by the confidentiality registry, as `test_permit_visibility` shows). Applied in SQL before `LIMIT` and `COUNT`.
- `depends` / detail `permits`: S3 has no link projection, so `_depends` reads the link events once for all ids in the page (one statement, `CAST(payload AS TEXT) LIKE` per id, exact match in Python), then one statement for the permits' states with the viewer filter. Two statements per call, never per row. Same rule as `guards.dependent_permits` (Approved, Active, Suspended; stored status).
- `guards.py` is not modified and not copied; `BLOCKS_REMOVAL` is imported. `views.py` helpers `_when`, `_text`, `_iso`, `EXPORT_FORMATS` are imported (no second filter helper).
- Readings: `Decimal(str(value))`, so the SQLite float 20.9 becomes `Decimal("20.9")`. JSONL writes decimals as their text (`default=str`), missing as `null`; CSV writes missing as an empty cell.

## Learnings (proposed)
- pg8000 over SSL in this sandbox hangs a second Postgres-parity test in one process (T01 and T02 files alike). Gate-pg needs a healthy host or a timeout in `dev/gate.sh`; a run has no bounded duration.
- SQLite returns NUMERIC as a float, so a reading stored as `30` exports as `30.0`. Exact text would need a TEXT column (a projector and DDL change, so a ticket).
- The ticket's Worktree and Branch fields differ from the dispatch (`/home/user/wt/ptw/t02` from `p2/ip-r3` vs `/home/user/wt/ip4/ptwt02` from `81f62b46`). Both were used as given; the work is on the dispatch branch.
