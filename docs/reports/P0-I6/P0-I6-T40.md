## Learnings (proposed)
- `Rec` is frozen, so after `submit` the actor must rebuild the record with the state the suite left it in (`_submitted`). Without that, the candidate filter in step 5 sees the pre-submit `Draft` state of a document created this step. The ticket's helper description does not mention this.
- The serial formula is `existing + created_so_far + 1`. The spec text ("plus one for each document this step has created so far") does not say the `+1` for the new document itself, but the provided test (first document is `Doc 001`) pins it. Worth stating in the spec.
- `FakeClient.query` raises on any filter term other than `title~` and `status:`. `records(title_prefix=...)` uses an empty query, so the actor is safe. A future actor that filters by other terms will need `FakeClient` extended.

## Open questions / Blocked
- **Rev Z.** The spec's step 5 has no rule for a document already at `Rev Z`; `chr(ord("Z") + 1)` would produce `Rev [`. The implementation excludes `Z` documents from candidates (they stay in review and are not revised further). If the supervisor prefers a different rule (for example a hard error, or allowing `Rev AA`), this is a one-line change in `_revisable`. It does not affect any provided test. Not blocking.
