## Learnings (proposed)
- `pkill -f <pattern>` matches the invoking shell command when the pattern text appears in that command, so it killed the Bash tool's own shell (exit 144). Use a PID from `pgrep` or a pattern that does not occur in the command line.
- A multi-line `cat > file <<'EOF'` inside a compound `&&` chain in the Bash tool did not create the file and the call then ran until the 120 s foreground timeout. The Write tool created the same file at once. For scratch scripts, prefer Write.
- The ticket's Context list does not include `docs/templates/haiku-report.md`, which the report requires. Reading it was necessary; the Context list could name it.
- Spec ordering detail that the code follows: `m` is drawn before the lines are read, so an empty line set still consumes the activity-count draw. The approved-document list is read once before the activity loop rather than per activity; this does not change any draw because no document changes status inside step 2.
