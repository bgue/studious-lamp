## Learnings (proposed)
- Whole-repo pyright is about 1.8–2 GB RSS per worktree. Several parallel implementers exhaust the host memory cgroup,
  and the kernel kills one run silently (exit 247, no output). Check `dmesg` for `oom-kill` to confirm. A supervisor may
  want to serialise `just check` runs or raise the memory budget.
- `NODE_OPTIONS=--max-old-space-size` does not avoid the kill; the cgroup limit is the constraint.
- `/usr/bin/time` is not installed here, so a `command -v ... && time-cmd ...; echo` chain silently skips the run.

## Open questions / Blocked
Blocked on the gate, not on the ticket's code. Question for the supervisor: should `just check` be re-run once the
other pyright runs finish, or should the memory budget or pyright scope be changed? Both are outside this ticket's
Allowed paths. Once `just check` runs to completion on an idle host, the expectation is no code change.
