## Q2: when the allocator is called for `quality.Checklist` today
At creation of the record only: `tl_core.services.records.create_record` calls `allocate_key` (via `numbering_for(...).find`)
in the same append as `Record.Created`, when the command gives no key. No later event allocates. So for S3: the envelope
`Record.Created` (and a number) exists from the first draft save unless S3 creates the record at submit; a draft that must
take no number needs either a record created only at submit, or a typed key at first save (the id) replaced at submit, which
the ledger cannot do (keys are fixed at `Record.Created`). S3 decides. Also for S3: `forms.Submission` with scope `company`
has no pattern (`{project}` needs a project scope). The allocator supports a company form (`{type}-{seq:4}`), but the spec
allows two blocks and the pinned count is two, so a third block (`forms.Submission` company) is a question for S3.
