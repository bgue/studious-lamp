## Learnings (proposed)
- `$` in the ticket's ULID pattern matches before a trailing newline, and jsonschema uses `re.search`. A pattern like `^...$` lets `"<ULID>\n"` through the schema while `_ULID.fullmatch` refuses it. The fixed sample list does not cover this.
- `just check` pyright step under `NODE_OPTIONS=--max-old-space-size=6144` exits 247 on a 16 GB host with about 13 GB already in use. Plain pyright is fine.

## Open questions / Blocked
1. Trailing newline: `to_json_schema([photo field], fmt=2)` accepts `[{"q": "q1", "value": ["<ULID>\n"], "note": null}]`, and `validate_answers` refuses it (`q1: must be photo file ids`). I kept the ticket's pattern exactly. Proposed fix, for a decision: `\Z` in place of the final `$`. Not applied.
2. `x-min` and `x-max` are carried only on `number` branches. The ticket names them only under the number value schema. Confirm, or say whether they should appear on every branch that sets them.
3. Pyright under `NODE_OPTIONS` is an environment problem. The orchestrator should decide whether to rerun `just check` on a host with more free memory, or drop the heap option.
