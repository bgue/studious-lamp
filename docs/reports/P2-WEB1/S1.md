## Deviations
Within scope, but beyond the ticket text (all inside Allowed paths); the human gate reviews them:
1. An agent principal is refused (401) on every non-open `/web/` path, whether the token came by cookie or by bearer (the ticket pins the cookie case only).
2. `AuthenticationMiddleware` takes `web_paths: bool = True`; `create_app` passes `False` when the web is off, so a switched-off web reads no cookie and `/web/` is an ordinary unknown path (401 without a token, 404 with one).
3. `create_app` adds a second `RateLimitMiddleware` for `POST /web/sign-in` sharing the JSON route's limiter (else the form would be a password-spraying path without the per-source cap).
4. `BODY_LIMITS` row is the prefix `/web/sign-in`; `POST /web/sign-out` has no body limit (CSRF reads its form). Open question below.
5. The manifest also lists the two upstream LICENSE files (hashed, with their SPDX id), beyond the three code files.
6. The sign-in form calls the JSON handler function `routes.auth.sign_in(SignInBody, ctx)` directly; sign-out calls `sessions.sign_out` (the JSON sign-out handler reads only the bearer header). `routes/auth.py` is untouched.
7. No `just gate` was run: the ticket's Acceptance says no pytest and no gate. One regression sniff: `pytest test_auth.py test_auth_review.py test_api_inbound.py` = 67 passed.

## Open questions / Blocked
- Should `/web/sign-out` and later unsafe `/web` routes get a body limit (a `/web/` row, S2 to size)? Today only sign-in has one.
- `TL_WEB` values other than on/off raise at start-up (`ValueError`); confirm that is wanted.
- Behind a TLS-terminating proxy the own-origin check needs `TL_WEB_ORIGIN`; document it in T7.
