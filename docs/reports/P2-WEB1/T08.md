## Learnings (proposed)
- "Only the offered actions" for a plain user on an awaiting-response technical item means two commands (`AnswerTechnical`, `CloseTechnical`); a check that names one will fail.
- A cookie jar that was never signed in sends no cookie, and the web answers 303 to sign-in, not 401 or 403. A missing sign-in reads like an auth refusal.
- An action POST needs `Origin` (or `Referer`) equal to the server origin, in addition to the CSRF token; with the token alone it is still `csrf_refused`.
- `GET /web/files/{id}/content` needs `?scope=project%3AP123`; without it the response is 422.
- The RFI number is `P123-RFI-0001`, not `RFI-0001`; `tl corr class set <number>` accepts it and makes the RFI restricted.
- `tl doc rev issue` by `demo` was refused once with "needs the controller access word" right after the rendition was added, then succeeded on retry with no change; not reproduced on a fresh ledger.
- Demo database names `tl_pytest_demo_<unix time hex>_<pid>_<hex>` carry their creation time, so a stale one can be dated from its name.
