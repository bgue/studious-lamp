# P2-INS-T05: constraint word on the Checks read

No ticket file; the brief was the spec (security, decisions Q5 and Q6).

## Change
- `tl_api/insights_sources.py`: new `sources_for(conn, holder, scope)`. It returns `SOURCES`, minus
  `constraint_findings` when the holder lacks `core.constraint.view` on the scope. The source is
  skipped, so hidden looks the same as nothing there (no error, count or placeholder).
- The route `GET /records/{id}/checks` (`routes/insights.py`) and the embedded client
  (`tl_tui/embedded.py` `checks`) both call it, so they behave alike. Agents keep the 403 on the
  constraint routes (test added).
- `tl_mcp/dev/sqlguard.py`: `telemetry_need` is in `DENIED_TABLES` (the SQLite authoriser) and has a
  text check, as `wh_secret` has.

## Tests
- `packages/tl-api/tests/test_checks_walk.py`: a person without the word sees no constraint
  findings while every other finding is unchanged. A person with the word sees them. The response
  with hidden constraints is byte-equal to the response with none. The agent gets 403 on the
  constraint route.
- Every shipped account role implies `read`, so the no-word person is built by patching the cached
  role table (`user: [user]`, no `read`). This is the only way found to get a person with a role and
  no word.
- `packages/tl-mcp/tests/test_dev_sqlguard.py`: a query naming `telemetry_need` is refused.

## Mutation
- Sentinel: `if True or holds_word(...)` in `sources_for` (the guard is always open). Killed (2
  failures in `test_checks_walk.py`). No other mutants.

## Gate
- `just check` passed.
- `just gate` on tl-core insights, `test_checks_walk.py`, `test_confidentiality_walk.py` and
  `tl_api`: 86 passed.
- `just gate` on `test_dev_sqlguard.py` and `tl_mcp/dev`: 42 passed. It is a separate run because
  `test_confidentiality_walk` exists in both tl-api and tl-mcp and the names clash in one run.

## Open

  there would help if the TUI test harness has a no-word person.
