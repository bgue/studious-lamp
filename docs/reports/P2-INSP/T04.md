## Learnings (proposed)
- A fresh `PlanInspection` returns version 2 (not 1); the handler writes two events. Print the version, do not assume it.
- Every account holds one of `admin`, `document_controller`, `user`, and `quality.inspection.plan` is `user`, so no account can be made that lacks the plan word through `world.person`. Use a user without the controller word to test the word gate.
- `ScheduleInspection`/`PlanInspection` expect record ids; `get_record` returns `type`, which the CLI checks for inspections and checklists.
- `just gate` prints only FAILED names; the pytest traceback needs `uv run pytest -q <file> -k <name>`.

## Open questions / Blocked
- Answers file format: the ticket says each object is `{"id", "value", ...}`, but the command model and `_answers` take `{"q", "value", "note"}`. The file is passed through verbatim as the model takes it, so an `id` key will be refused by the handler. Tests use `q`. Please confirm the intended key.
- `--answer Q=VALUE` values: the ticket does not say. A value that parses as an int or float is sent as a number (needed for number questions), otherwise sent as text.
- Checklist key that does not resolve (or is not a checklist): printed as `error: no record <KEY>`, the same rule as the subject. The ticket names no text for it.
- `export` lists up to `insp_views.MAX_LIMIT` (500) rows, since the ticket gives no limit.
- `show` prints empty values as `—` (tui-layout), while `ls` uses `-` (cell helper, as punch does). Confirm that split is wanted.
- `reinspect` prints `reinspected <new key>`, the key of the new inspection the handler returns.
