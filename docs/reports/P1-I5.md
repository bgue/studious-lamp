# Report — P1-I5 Correspondence core (M10), clock engine, General and Document-control domains

Branch `p1/i5`, merged with trunk (P1-I4 and P1-SEC1). Plan: [docs/tickets/P1-I5/README.md](../tickets/P1-I5/README.md). Decision record: [ADR-0016](../adr/0016-confidentiality-enforcement.md). Module page: [correspondence](../modules/correspondence/README.md). Runbook: [correspondence](../runbooks/correspondence.md).

## Outcome
Objective met: yes. The suite has a correspondence module: letters, emails and minutes are received or issued, threaded, answered and counted against response clocks, and read back through one master register that also lists the document-control transmittals of I2.

- **Items.** `tl corr` receives by upload, triages (a suggestion engine proposes a domain and subtype; a person confirms; an agent only proposes), drafts, issues (a controller's act: the letter is rendered to a deterministic PDF, the send is a stub, the clocks start), records responses, closes, voids and supersedes.
- **Clocks.** Calendar and working-day clocks on a project calendar, with warnings, pause, resume, restart, meet, cancel and a sweep that records `Warned` and `Expired`; a contractual time bar can be restarted or cancelled by a controller only.
- **Email in.** A bounded `.eml` reader and `tl corr mail ingest`: the party is matched by its domain, the message is threaded by its headers, the item number or its subject, and the original and the attachments are kept.
- **Domains.** The General and Document-control domain definitions, compiled and validated; parties, contacts and contract clauses.
- **Confidentiality (ADR-0016).** Classes `internal`, `restricted`, `privileged` (the accounts named on the item); an unknown class is read by nobody. Every read path filters through the viewer: registry, views, the API, MCP tools and resources, the CLI and the TUI, webhooks, the lake and the register export. Walking tests enumerate every GET route and every read tool, on both adapters.
- **Entry points.** CLI `tl corr`; API routes and `ApiClient`; MCP read tools and one proposal tool (`propose_triage`); the TUI correspondence screen on **F5**; reports (master register, responses due or overdue, running clocks).

Demo path verified: `just demo P1-I5` passes its eight clauses on SQLite and on Postgres on the merged tree (see Showcase). Verified on a fresh clone: not repeated; the demo and the gates ran on the final tree of the `p1/i5` worktree.

## Security review
Nineteen fixes (`P1-I5 review 1` to `19`) over several fresh-context reviews. The classes of finding, each fixed with a test that fails without the fix:

| Area | Fix |
|---|---|
| Webhooks and the lake | Judge the stream of an event, not only its subject (1) |
| Files and links | A file of a hidden record does not count for dedupe (2); link commands answer "no such link" for a link with a hidden end (4, 14); a post that tags a hidden record reads as absent (6, 14); a generic edit says "no such record" first (5) |
| Lock-out | A controller not named on a privileged item can name and unname readers by id (3, ADR-0016 section 2); the answer shows an uncleared controller nothing, no number and no class (17) |
| Sweep | Reads every clock as the system in pages, says which clocks it could not judge (7); its answer holds only the events of clocks the runner may read (16) |
| Time bars and MCP | Restarting or cancelling a time bar is a controller's act (8); the MCP server sets the viewer on every call (8) |
| Text and export | `clean_text` on every command text that becomes record text; the export quotes a leading pipe (9) |
| EML parser | Refuses a message of hundreds of thousands of parts before parsing (10); headers that name a hidden message do not join its thread (10) |
| Transmittal and walks | The transmittal's events are scanned for hidden records (11); the walks gain MCP resources, the command differential and run on Postgres (11, 12, 13) |
| Replies | A received reply or an item moved into a thread takes the class of what it answers, and for `privileged` the named accounts (18); this is for new items only: moving an existing item into a higher-class thread, or making it answer one, is a controller act, refused to a plain user and recorded as a class change for a controller (19; L-P1-I5-9) |

Accepted, as known: a caller-chosen `post_id` that is taken says it is taken (a 26-character id to guess).

## Deviations from plan
- **The correspondence screen is on F5, not F12.** P1-I4 took F12 for the schedules screen; the schedules screen stays where it is. F5 is free on the main screen (the modals use F5 to reload, and a modal's binding wins). The demo, docs, tests and key map were changed with it.
- **Merge of trunk.** Registries were edited additively as planned; conflicts were in lists of modules, commands, routes, tools, tests that pin counts and the generated files, which were regenerated (`just gen`, `python -m tl_api.openapi`, `uv lock`), not edited. P1-SEC1 removed `actor_roles` and the roles on a proposal accept; no P1-I5 caller used them (the controller gates read the viewer level, triage proposals carry no roles).
- **Found by the first full run after the merge, none by the per-file runs:** the controlling set test did not list the 13 correspondence controller acts; both walks (API routes, MCP tools) needed values for the new modules' arguments; `propose_triage` is a proposing tool; the items of `referenced_ids` had no length limit in the model and in the MCP schema (now 128 characters each, as an item number); `tests/query/test_injection.py` asserted that the word UNION is in no SQL, and the confidentiality filter of the correspondence module has a UNION of its own, so it now compares the count of each fragment with a harmless value.
