## Learnings (proposed)
- The ticket's Interfaces block states `header_line` and `footer_lines` with `width` as a cell count; the provided tests and rules agree that `set_cell_size(text, n)` already includes the ellipsis cell, so "cut to N cells with an ellipsis" means N cells total (N-1 kept + `…`). That reading is what made all 11 tests pass; the ticket wording could say "total N cells" explicitly to save a re-derivation.
- `ruff format packages/tl-tui` also formats `tests/`, so a copied provided test file must be re-checked with `cmp` after formatting. It was unchanged here.
- `Widget` has neither `_redraw` nor `on_resize` in this Textual version, so both names are safe to use on the widgets.

## Open questions / Blocked
None blocking. Two unspecified edge cases were resolved by guard clauses and are flagged for the reviewer:
1. `width <= 0`: `header_line` returns `""`, and `_cut` returns `""` (the ticket's `set_cell_size(text, width - 1) + "…"` would ask for a negative size). No test covers it.
2. Footer right-aligned count when the terminal is narrower than the count itself (`width < cell_len("N selected ")`): the left part is dropped and the gap is clamped to 0, so the count line is then wider than `width`. The ticket does not say what to do here; no test covers it. Confirm whether the count should be cut instead.
