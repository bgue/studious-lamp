## Learnings (proposed)
- `ruff format --check` runs inside `just check`, not only `ruff check`. Code that passes pytest can still fail `just check` on one wrapped f-string. Run `uv run ruff format <file>` on each touched file before `just check`.
- The ticket's `check()` wording `"<doc>: depends on <dep>, which is not a company package"` is ambiguous. The provided test asserts `prj.P123@1.0.0` appears in the message, so `<dep>` means `name@version`. Tickets should write `<name@version>`.
- The module docstring of `registry.py` still begins "STUB: the bodies below are implemented by P0-I2-T01". It is stale after this ticket. I left it because the ticket says to keep docstrings.
- `pyright` strict passed with no `type: ignore` once the `yaml.safe_load` result was annotated `Any`.

## Open questions / Blocked
none blocking. Interpretations for the supervisor to confirm:
1. `adopted` rule (1): the highest version is taken among that project's own documents of the name, not among every stored version of the name. The two differ only if another project's document carries a higher version of the same name.
2. `adopted` rule (2): "those documents" is read as the documents chosen by rule (1), not every stored document of the project.
3. `adopted`: a `depends` entry pinned to a stored non-company package is skipped (`check()` reports it). A pin to an unstored version raises `PackageError` from `get()`.
4. `parse_package`: an error with an empty location (for example a model-level validator) is rendered as `(document)`. The spec says `<dotted loc>` and does not cover the empty case.
5. `load_package` also wraps `OSError` and `UnicodeDecodeError` as `PackageError`, and checks the file name after parsing, since the expected name comes from the content. The spec is silent on both.
6. `projects()` returns the distinct non-`None` `project` values of all stored documents.
