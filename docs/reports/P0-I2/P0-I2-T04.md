## Learnings (proposed)
- `EffectiveCache` keys on `schema.hash` alone. `EffectiveSchema.hash` defaults to `""`, so two un-hashed schemas share cache entries. Callers must `with_hash` (or set `hash`) before validating; the provided tests set explicit hashes (`"kinds"`, `"no-custom"`) for this reason. Worth a line in the tl-schema docs.
- The `EffectiveCache.get_or_build` builds outside its lock, so a `build` callable may call the same cache (used here: the validator build reads `record_json_schema`). Computing `document` first, as the ticket's lambda implies, avoids depending on this.
- `jsonschema` is already a `tl-schema` dependency (`packages/tl-schema/pyproject.toml`), so no dependency change was needed.
