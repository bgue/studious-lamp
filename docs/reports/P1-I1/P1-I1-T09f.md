## Learnings (proposed)
- The ticket's pasted stub import list omits `TagOut`, which STEPS 3 names. Adding it was needed; a future stub should include every name its STEPS use.
- `just test-parity` takes about 65 minutes alone (3594 cases). Under concurrent parity runs in other worktrees, `test_the_stream_carries_own_writes_and_another_process_writes[postgres]` stalled for more than 25 minutes. It passed in 2.5 s alone and passed on the next full run. The supervisor may want parity runs serialised, or the test's SSE read wait bounded.
- Each pytest run uses its own database (`tl_pytest_<hash>_<pid>`), so concurrent runs do not share a database and did not collide on data.
- Run long acceptance commands (`just test-parity`) with `run_in_background`; a foreground call stops at 600 s and the process keeps running detached.
