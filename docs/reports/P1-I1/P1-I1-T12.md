## Deviations
Two small deviations from the STEPS text, both inside the ticket's Allowed paths:
- `made = rec.create_tag(...)` is written as a bare call. The `made` name is never read, and ruff F841 would fail `just check`.
- The `next_number` filter uses `str.isdecimal()` rather than "all digits" (`isdigit()`). `isdigit()` accepts characters such as `²` that `int()` rejects, so `isdecimal()` is the variant that cannot crash on a stray key. For ASCII keys the two behave the same.

## Learnings (proposed)
- `just test-parity` is the whole-repository parity suite, not a tl-sim check. It took 71 minutes here with three other worktrees running it at the same time. A ticket that asks for "the parity run" should name the scope (for example, a package path or `-k` filter) and roughly how long it takes. An implementer cannot tell which parity output is expected.
- Running `just test-parity` in the foreground from an agent tool hits the tool's 600 s limit. The recipe is then signalled (SIGTERM) and the log shows `terminated by signal 15` with no summary. Run it in the background with a log file.
- The STEPS line `made = rec.create_tag(...)` would trip ruff F841 once implemented. Tickets that give STEPS code should either omit the unused name or state that it is discarded.
