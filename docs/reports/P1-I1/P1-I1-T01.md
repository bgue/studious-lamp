## Learnings (proposed)
- PyYAML reads an unquoted `2026-01-01` as a `datetime.date`, and `StandardsDoc.effective_from` (a `str`) then fails with "Input should be a valid string". I checked this by running the model. Quote every date in a standards file. The same applies to numeric-looking codes: an unquoted `code: 10` becomes an int and `ValueDef.code` rejects it. I quoted the Area codes "10" to "50" and the dates and the version.
- In flow style (`- {code: 47, label: Unit 47, Hydrotreater}`) a comma inside a label ends the scalar. Quote every label that contains a comma, as in the ticket's example "Unit 47, Hydrotreater".
- `ValueDef` has no `definition` field. The "one-sentence definitions" in the ticket can only go on the code lists, the patterns and the tag classes. Values get a label only.
