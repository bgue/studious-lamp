## Decisions
- **ADR-0010 second addendum** (`generic_guards`, `by_module`, link-life commands, reserved relation, reserved `@`): the module seam can say which generic commands a type allows and under which state.
- **ADR-0011, document-control permissions in Phase 1:** controlling acts (issue, supersede, void, confidentiality, signed copies, issue a transmittal, on-behalf, override, link recovery) are the admin's; everything that prepares work is open to a signed-in person; agents propose only; no per-record access lists; the writer lock serialises concurrent admins.
- **ADR-0012, class-aware stale pins (owner decision, accepted 2026-10-13):** classes are ordered review < construction < record, and a pin goes stale only when a newer revision is issued in the same class as the pinned revision or a later one. A pin on a revision with no class keeps the old rule, voiding or superseding flags every link, and a floating link never goes stale from a revision. The change is in `resolver.py` (`affects_pin`) and leaves the core link interfaces alone. It replaced the literal brief §7.3 reading (any new issue flags), which flagged a construction pin whenever a review revision was issued.
- **Import registers documents only;** the legacy revision, status and date are a note in the description. Revisions with files come with P1-I8.

## Showcase
An interim screenshot tour of P1-I0 to P1-I2, generated from the demo state, is [PHASE-1-TOUR.md](PHASE-1-TOUR.md) (`uv run python dev/tour/phase1.py`).

Four things to show a document-control person. The demo state for the first three is the ledger after clause 4 of
`dev/demos/P1-I2.sh` (standards and the document pattern loaded; tags `47-FV-1001` and `47-FV-1002`; `ISO-1234` with
revisions A (IFR), B (IFC), C (IFR), D (IFC); both tags linked to `ISO-1234`, pinned to B; signed in as `demo`). Build it by
running the commands of clauses 1 to 4 of the script against a dev ledger (`tl init --dev`, then `tl login demo`).

1. **The document register with a status class per revision.**
   - Where: TUI `F7`, highlight `ISO-1234` (the panel lists A to D with `IFR review` / `IFC construction`, files and links); on the shell `uv run tl doc show ISO-1234 --project P123` and `tl doc ls --project P123`.
   - Standard activity: a document register that lists each document with its latest revision and status.
   - Novel approach: the document keeps one current revision per status class, so a revision issued for review and one issued for construction are both current, each shown with its class, instead of one flat "latest".
   - Unique value: the builder sees the revision to build from while the reviewers see theirs; nobody argues over which revision is "current".
2. **A stale pin and the re-pin diff.**
   - Where: `uv run tl doc stale --project P123` lists `47-FV-1002` pinned B, current D; `uv run tl doc repin <link> --project P123` shows the diff (status, issue, files, pages) and `--apply` moves the pin. In the TUI: `F7`, highlight `ISO-1234`, `r`, then Enter to confirm or Esc to leave it.
   - Standard activity: noticing that a drawing a tag depends on has a new revision, and updating the reference.
   - Novel approach: a link pins a revision (or floats), the rule is class-aware (an IFR issued after an IFC leaves the IFC pin alone, ADR-0012), and the re-pin shows what changed before it asks for a yes.
   - Unique value: an engineer re-pins knowing what changed, and is not warned about review drafts nobody builds from.
3. **A transmittal.**
   - Where: TUI `F7`, highlight `ISO-1234`, `t` (tick `ISO-1234@D`, type a subject, purpose and recipients, `ctrl+s`); on the shell `uv run tl transmittal create --project P123 --subject "Isometrics for construction" --purpose for_construction --to "Site Office:Acme Construction:site@example.com" --revision ISO-1234@D`, then as an admin `tl transmittal issue P123-TRN-0001` and `tl transmittal show P123-TRN-0001`.
   - Standard activity: sending a formal transmittal that records what went to whom and why.
   - Novel approach: the items are the exact issued revisions, the draft is anyone's work and issuing is an admin's act, and the response is recorded on the same record.
   - Unique value: a provable answer to "which revision did we send them, and when".
4. **The legacy register import preview.**
   - Where: `uv run tl doc import dev/seed/legacy/dms-document-register.csv --mapping dev/seed/templates/document-register-dms-export.yaml --project P123` (preview), then as an admin with `--apply --skip-invalid`. State: the standards and the document pattern loaded (clause 1).
   - Standard activity: loading the old DMS document register into the new system.
   - Novel approach: the file is judged against the live numbering pattern, code lists and the command's own limits before anything is written, every refused row says why and on which line, and applying is one unit of work with the import job named in the history.
   - Unique value: a migration done with the problems in view and nothing half imported (9 documents in, 7 rows refused with reasons in the sample).
