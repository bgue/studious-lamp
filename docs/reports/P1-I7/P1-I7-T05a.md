## Learnings (proposed)
- Strict pyright rejects the STEPS' plain `access=access` for `RegisterEnricher` (a `str` typer option into the `AutomationAccess` Literal). A `cast` to the Literal keeps the runtime validation in the service; a future ticket with the same shape should expect this.
- `line()` joins with two spaces. The provided tests check `tl enricher show` and `tl enrich show` with single spaces, so those commands need f-strings, not `line()`. The ticket's STEPS say only "print" for them.
- One provided test file of 15 cases took 39 s and 53 s on this box for two runs of the same code.

## Open questions / Blocked
Not blocked. One open question for the supervisor, not covered by the provided test:
- `enricher register` builds `RegisterEnricher(actor=..., source=..., scope=..., name=..., access=..., **body)`, as the STEPS say. If the JSON file contains a key that is also passed by name (`name`, `scope`, `actor`, `source` or `access`), Python raises `TypeError: ... got multiple values for keyword argument`. `service_errors()` does not catch `TypeError`, so the user sees a traceback instead of `error: ...`. AGENTS.md says never a traceback. I did not add a guard, because the STEPS fix the call. Proposal for a decision: reject those keys with `fail(...)` before the call, or catch `TypeError` in `register`. I have not run this case.
