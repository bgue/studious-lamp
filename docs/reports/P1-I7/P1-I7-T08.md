## Learnings (proposed)
- The profile checks use one disallowed construct each (a single call, a lambda, a partial application or a regex literal), so each expected code list is exact. The runtime returned exactly the listed codes for all seven refused checks (the seed's `refuses-eval` included): `function_not_allowed` for the disallowed calls and `not_allowed` for the three constructs.
- `WebhookExecutorConfig.url` is a plain `str` with `max_length=2000`. Credentials and fragments in a URL are therefore not rejected at config time; they surface as `egress_denied` at execution, which is the behaviour the golden cases pin.
- The coverage tests in both runners stop at the first failing category in each assertion, so the first run reports only one missing category per test. Counting the seed against `MINIMUM` before the first run saves a round trip.
- AGENTS.md's "Read next" for an implementer names `docs/build-spec/01-tiers.md` §4, which the ticket's *Context* list does not include. I followed the ticket's *Context* list, as the task instructed.
- Regenerating the JSON files with `json.dumps(indent=1)` keeps the seed formatting, but adds a trailing newline the seed lacked. The diff therefore shows 2 deleted lines (the old final brace line), which is formatting only.
