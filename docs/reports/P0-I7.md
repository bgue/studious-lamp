## Outcome
Objective met: yes. The ledger is sealed into signed, hash-chained archive segments kept apart from the database. `tl archive verify` reports the first divergence, `tl restore --from-archive` rebuilds an empty SQLite or Postgres database from the archive alone, and the restored `cur_*` tables equal the originals. SQLite has an online-backup snapshot and a verified Litestream configuration; Postgres has a pgBackRest configuration and a drill on a scratch cluster. A DuckLake copy (bronze events, silver current state) is synced incrementally by seq, one snapshot per sync with its seq range in `_tl_sync`, and answers DuckDB queries and a read-only, limited, logged `lake_query` (CLI and MCP tool) that states the ledger seq it reflects.

Demo: `just demo P0-I7` (`dev/demos/P0-I7.sh`). It seals a small ledger, verifies it, tampers with a copy (verify names the first divergence: `file_hash segment=... events.ndjson differs from its hash`, and the untouched archive still verifies), restores into a fresh database and checks events and current state equal, then runs the lake section (`dev/demos/P0-I7-lake.sh`, also runnable alone as `just demo P0-I7-lake`) on the restored ledger: sync, the six demo queries, an incremental sync, time travel, nine refused statements, the audit log, and a rebuild. It ends with `as of seq N` equal to the archive's last seq.

## Deviations from plan
- WS-A added `tl ledger verify`, `verify_ledger` and `just drill`, and changed webhook delivery for a subscription with no signing secret (S16) by orchestrator ruling; details in `P0-I7-A.md`.
- Bronze `events` keeps `recorded_at`, `effective_at` and `payload` as text exactly as hashed, so a lake can re-verify event hashes; `test_bronze_matches_archive.py` shows the lake table and a sealed `events.parquet` have the same columns, types and cells.
- Silver timestamps are `TIMESTAMP` holding UTC, not `TIMESTAMPTZ` (reading zone-aware values in Python needs `pytz`, which is not a dependency).
- The original plan's WS-B ticket "`lake_query` MCP registration" failed the Haiku-ability checklist (it adds a parameter to the public `tl_mcp.build_server`), so the supervisor built it and the ticket became the runbook section.
- A lake is rebuilt from the archive by `tl restore` followed by `tl lake rebuild --yes` (silver is mapped from the restored current-state tables). Loading bronze straight from the Parquet segments is not built.

## Escalations and decisions
- Orchestrator rulings applied: the lake runbook's business-hours answer (sync yes, rebuild no); the restore transaction and schema-hash warnings; the dispatcher cursor after a restore; the webhook secret hold.
- Review findings closed: guard CTE scoping and path-like names, audit of every call, ASCII-escaped audit lines, a result byte cap, NUL, path-free errors, and fixed path-free sentences for lake failures in the MCP tool (`docs/reports/P0-I7-B.md`).
