## Cursor choice
`rule_cursor` (`name`, `last_seq`) with consumer name `awp.readiness`; its shape fits. If the table is absent the
position is kept in memory. A follower with no cursor row starts at the outbox head and first queues an evaluation
for each IWP in Constraint check or Ready (`hooks.fallback_ids`, cap 200 per scope), so nothing earlier is missed.

## Known limit
Without a `rule_cursor` table the position is in memory only: a worker restart cold-starts at the head and queues the
IWPs in Constraint check or Ready (cap 200 per scope); an IWP beyond the cap waits for its next event. On an event
failure the batch stops and the cursor stays (retry next poll); the same seq is skipped after 3 consecutive failures.
The cursor UPDATE is guarded by `last_seq < :seq`.
