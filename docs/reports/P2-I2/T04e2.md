## Learnings (proposed)
- `cur_core_constraint` has no `status` column; the state is `cur_core_record.status` (joined on `id`).
- Outside `just`, `TL_ENV` is unset and `acting()` refuses `--actor` with "not signed in"; a direct `uv run python` script needs `TL_ENV=dev`, as `conftest.py` sets it for pytest.
- On a dev ledger file the session viewer is `Viewer(user:dev, level 1)`, which reads restricted records; a hidden-subject check has to run as the lowest clearance.
- The ticket's commit subject (`T04e2:`) and the repo's ticket-ID form (`P2-I2-T04e2:`) differ; this commit uses the ID form.

## Open questions / Blocked
- `awp_write._parts` prints the full `--target-ref` value when its shape is wrong (for example `--target-ref PO-1` with no colon). The ticket names `_parts`; the value is a reference, not a description. Should the CLI use its own split that does not echo the value?
- The implementer prompt and the attribution reminder name different models for the commit trailer. This commit uses the attribution reminder's line. Which one should stand?
