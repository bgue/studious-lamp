## Learnings (proposed)
- `iwp_facts.pinned_document_links` lists only active, pinned links, so a stale or floating pin never reaches a check that reads the facts. The check now reads the IWP's reference links itself.
- A pin on a document the viewer may not read must still count in the total (as not current). Dropping it changes the answer shape; the resolver's viewer filter makes it answer like a missing document.
- Writing a restricted document through the commands fails with `RecordNotFoundError` under the default viewer. Create, issue and read it inside `tl_core.confidentiality.system_view()`.
- `ruff format` rewrites files in place; an editing agent sees them as "changed on disk".
- `dev/accept/P2-W0/W0-B1.py` (line 138) and `dev/demos/p2_w0_demo.py` (line 318) assert the exact set `{"materials_reserved"}` and will fail now. Not run; outside allowed paths.

## Open questions / Blocked
1. Pin currency (needs the orchestrator's decision): the check uses the resolver's state. Under ADR-0012 an IFC pin with a later IFR (a lower class) resolves `current`, so it is counted current. The orchestrator's sentence ("current only if it points at the current issued revision") would count it behind. I followed the ticket and the resolver; I did not change either.
2. Viewer: confirmed as built. A job read (no viewer) sees internal documents; a restricted pinned document answers like a missing one. The filter is not widened.
