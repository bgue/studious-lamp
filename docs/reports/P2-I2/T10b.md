## Learnings (proposed)
- `tl awp worker --once` polls one batch of 100 outbox events per run (`readiness/follow.py`, BATCH). After a setup backlog of several hundred events, IWP events are not seen until several runs. The demo runs the worker 8 times after setup and 2 times per evaluation.
- The expected-link registry reads only `schema/fixtures/links/`. A class-level `tl:expects_link` in `schema/modules/` is not reported by `tl link list` until the fixture repeats it.
- `tl doc stale` lists fixed pins only (`--pin A`). A floating pin never goes stale, so the demo pins at revision A explicitly. Stale line: `<IWP> -> <doc> pin A current B <link id>`; the link id is the last field.
- `tl derive publish` (CLI) refuses an MTO target; MTO publish is the API command `PublishDerivedMto`.
- `tl awp iwp create` prints no sizing warning. It shows only in the TUI backlog sizing view (key `z`) and in the event payload.
- The web readiness page shows check labels ("Documents current"); the TUI and API show names (`documents_current`).
- `tl events tail` takes `-n`, not `--limit`.
- The sim's `--run-id` becomes the project scope (`sim-<run-id>`).
