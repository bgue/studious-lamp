## Learnings (proposed)
- `tl awp worker --once` polls one batch of 100 outbox events per run (`readiness/follow.py`, BATCH). After a setup backlog of several hundred events, IWP events are unseen until several runs. The demo runs the worker 8 times after setup and 2 times per evaluation.
- The expected-link registry reads only `schema/fixtures/links/`; a class-level `tl:expects_link` in `schema/modules/` is not reported until the fixture repeats it.
- `tl doc stale` lists fixed pins only (`--pin A`). Floating pins never go stale. Stale line: `<IWP> -> <doc> pin A current B <link id>` (the link id is the last field).
- `tl derive publish` (CLI) refuses an MTO target; MTO publish is the API command `PublishDerivedMto`.
- `tl awp iwp create` prints no sizing warning; it shows in the TUI backlog sizing view and the event payload.
- The web readiness page shows check labels ("Documents current"); the TUI and API show names.
- The sim scope is `project:sim-<run-id>`. A manual constraint's owner must be an account; the sim suite provisions tokens only, which is why `ensure_people` exists.
- The combined gate over `packages/tl-cli/tests` takes about 40 minutes; one run hit the memory limit on a concurrent command.
