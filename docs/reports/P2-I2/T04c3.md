## Learnings (proposed)
- `ux_cur_core_record_scope_key` already makes keys unique per scope, so the F3 note "unique per type, not per scope" in the ticket is inaccurate.
- Dev tokens need `TL_ENV` in dev, test or ci (`auth/env.py`), otherwise a dev-token reader gets 401 in a script.
- No account role in the shipped table lacks `read`, so a real "role without word" reader can only be made by stubbing `holds_word`.
