## Learnings (proposed)
- Route `guard(VIEW_WORD)` does not enforce `core.constraint.view` against the access-word table. `RoleAuthorizer.authorize` refuses only roleless accounts and agents not in `AGENT_ACTIONS`; the word table is read only by the CLI (`constraint_read.require_view`). So the API and the embedded client can disagree for a person with a role that lacks the `read` word. The embedded client follows the CLI.
- `ConstraintRow` is a stdlib dataclass, not a pydantic model, so `ApiClientBase._model` (`model_validate`) fails on it; `get_constraint` uses `TypeAdapter`.
- The embedded client imports private names from `tl_api.routes.constraints` (`_rows`, `_KEY_SQL`, `_ANY_KEY_SQL`) to avoid a second SQL path. Same precedent as `_note` from `routes.awp`.
- In a loop, a lambda that captures the loop variable trips ruff B023; pass the client as an argument to a helper.
