## Learnings (proposed)
- One key, two meanings in one TUI file family: `iwp_register.py` binds `r` to Ready on the IWP log, and `IwpScreen` binds `r` to Readiness. The first-pass docs took the screen's binding for the log. The per-screen key tables in `docs/reference/awp.md` are the place to check this.
- IWP and readiness CLI reads check no access word (`awp_iwp_read.py` docstring); constraint reads check `core.constraint.view` (`constraint_read.py`). The awp README's general rule "all other reads need `awp.view`" does not cover these verbs.
