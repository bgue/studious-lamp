- A file id names no scope, so `fetch_file(file_id, dest_dir)` uses the scope remembered by `list_record_files`; a file never listed raises `UnknownFileError`, the same error as a hidden or missing one (the message is normalised to `no file '<id>'`).

- `RecordActions.state` is the raw status (`Void` once voided, `None` until the record's first move); no workflow file is read.
- `SupersedeRevision` is offered for any issued current revision; the replacement is typed data, not state.
- `tl_mod_engineering/imports/apply.py` imports `ENDED` from `actions.py` (it moved from `handlers/tags.py`); no behaviour change.

## Learnings (proposed)
- `create_app` sets the process-wide derivation file service: a test of "no file service" must use `derivation_store.use_files(None)`.
- Driving each command for real inside a unit of work that is rolled back is a cheap oracle for "offered == allowed"; it cannot see a change to a table the handler also reads, so keep literal expectations beside it.
