## Learnings (proposed)
- Pyright strict on YAML data: `isinstance(x, dict)` narrowing an `Any` produces `dict[Unknown, Unknown]` and fails `reportUnknownVariableType` / `reportUnknownMemberType`, even when the outer value is annotated `Any`. The ticket's recipe ("annotate as `Any` and narrow with `isinstance` plus `cast`") is not enough for nested mappings. What worked: a helper `_as_mapping(value: object) -> dict[str, Any] | None` that returns `cast(dict[str, Any], value)` after the `isinstance` check, and using it at every level.
- `just test` takes about 70 seconds on this worktree (1012 tests), so run the single ticket test file first and the full suite once at the end.
- `uv sync --all-packages` prints a long list of installed packages; pipe-free runs are fine, but the output is large.

## Open questions / Blocked
none blocking. The following are decisions where the spec is silent or where the spec's wording conflicts, for the supervisor to confirm:

1. **Self-loop under `either`.** A link `a -> a` (from_id = to_id = the record) is counted once by the OUT statement and once by the IN statement, so `either` reports 2 for it. The spec says "`either`: add both counts" and the `unmet_expectations` docstring says "A link is counted once." I followed the two statements as specified. No test covers a self-link. If the supervisor wants one count, the fix is a different SQL shape for `either`, which is a spec change, so I did not make it.
2. **Empty YAML file.** `yaml.safe_load("")` returns `None`, which is not a mapping, so an empty `.yaml` file in `schema/.../links/` raises `"<name>: a schema file must be a YAML mapping"`. This is the literal reading of the spec. Confirm this is the intended behaviour, or whether an empty file should be an empty registry.
3. **`tl:expects_link` value that is neither a mapping nor a list** (for example a plain string or `null`). The spec defines messages only for invalid entries, so I raise `"<source>: <Class>.tl:expects_link must be a mapping or a list of mappings"`. This message is my wording.
4. **Read errors.** `UnicodeDecodeError` from `read_text(encoding="utf-8")` is reported with the same `"<name>: cannot read file: ..."` message as `OSError`. The spec says "Read errors" without listing exception types.
5. **Non-string YAML class keys** (for example `1:`) are converted with `str()` for the record type; no test covers this.
