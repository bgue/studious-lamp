- Ref rule (Q1): a ref must sit in the module's own package; the ten in-tree modules alone may point at `tl_api.routes.`,
  `tl_mcp.`, `tl_cli.` (`IN_TREE_SURFACES`). New modules (QR, INSP, PTW) keep every ref in their own package.
- Delegation marks live in `tests/tools/delegation_marks.toml` until modules carry row `meta` (D6); missing means excluded.
- The scaffold carries no example command (an access-worded handler is core work); `tests/ext_demo` is the worked command (D7, D11).
- No `errors` hook: new modules raise the core error classes (Q3); opening a module tool to agents is still a `MCP_ACTIONS` edit (Q4).
  Both are DEFERRED rows.
- The requisitions commands are now served by the API (Q2, additive routes).

## Lesson: a trunk merge brings rows your pins do not know
The trunk merge at DONE brought the requisitions module (P2-I4A), whose commands the new hooked table now serves. Three exact pins
(controller set, command count, agent decisions) went red. Any branch that builds a table from installed modules should re-run its
table pins right after each trunk merge, not only at DONE.
