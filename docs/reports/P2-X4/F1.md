# P2-X4-F1 report

## Root cause
The `module_command` fixture in `test_agent_filing_check.py` declared
`command_words={"CreateRecord": "controller"}`. `CreateRecord` is a core command. X4 (S4/S6)
refuses a module that names a core command, whole: `command_index()` skips it and
`module_commands(reserved=...)` refuses it with a warning. The fake module was therefore skipped,
`CreateRecord` was treated as core, and a `viewer` grant (any module role) was enough to file.

## Verdict
The fixture was stale. The code is correct and not a regression: a module must never gate (or
loosen) a core command, and `check_filing` takes the core path for it, as designed. No code changed.

## Fix
Test file only. The fixture declares its own module command `VaultCreate` (a `CreateRecord`
subclass defined in the test module, so not a `tl_core.` name) with `command_words` and a
`ProposableCommand` (tool `vault_create`). `cmd()`, `do_submit`, `do_propose` read the active
class and tool from `_ACTIVE`, which the fixture sets and resets; the core fixture keeps
`CreateRecord`/`create_record`. No assertion changed or weakened.

- ruff check and format clean; pyright on the test file 0 errors.
