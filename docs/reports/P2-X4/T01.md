## `_group_name` rule
- attr `app`: the module part of the ref (`tl_cli.corr:app` gives `corr`).
- attr `<x>_app` with non-empty `<x>`: `<x>` (`tl_cli.req:wo_app` gives `wo`).
- anything else: `ValueError` naming the Python module only.

## Learnings (proposed)
- A ref whose attribute is neither `app` nor `<x>_app` (e.g. `tl_cli.awp:NOPE`) raises `ValueError` from `_group_name` and is not skipped as a hook failure, unless the name rule is checked after resolve (done here). Missing `_app`-suffixed objects are the skip case.
