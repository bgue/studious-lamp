# P2-X4 S6 — SR-X4 F1, F2, F3 fixes

Deviations first:
- F3: `_check_ref` raises `ModuleLoadError` (fixed text `module 'x': cli_groups names no group attribute`, no ref) at spec build,
  the same path as every other malformed ref (the process stops); it does not "skip the module", because a bad shape never gets
  past `ModuleSpec` construction. `_group_name` is unchanged and can no longer see a bad ref.
- `refused_hook(spec, kind)` is new public API in `tl_core.modules`; `module_commands` and `hook_failures` gained an optional
  `reserved` argument (default empty, so callers are unchanged). A refused command module logs on `tl_core.modules`.
- Module routers keep their place in the mount order; core paths are read from the core routers up front (`_core_route_paths`), so no
  existing route order changed. MCP module tools now register last (after the inline core tools), staged through `_StagedServer`.
- Fixtures changed: `test_module_hooks_api.py` and `test_module_conformance_walk.py` (api) had unguarded fake routes, now guarded;
  the `module_commands` counting stub takes `*reserved`. Spec file: `docs/tickets/P2-X4/S6-sr-fixes.md`.
- Gate names: all named files exist. `just gate` on `test_commands.py` was OOM-killed (137) four times under the other live run;
  its 266 tests pass in three direct pytest chunks. Full-repo pyright was OOM-killed (247) three times; touched files are clean.

What changed
- F1 command: core rows built first (`_CORE_COMMANDS`); a module naming a core command is skipped whole, one fixed warning.
- F1 tool: module registrars write to a staging server; a module whose tool name hits a core tool, an earlier module, or itself is
  skipped whole (fixed warning). F1 route: a path equal to a core or earlier-module path (param names erased) skips the module.
- F1 CLI: `_add_module_groups` runs last in `main.py`; a group name already a root command or group skips the module.
  `tl new module NAME` refuses a NAME that is a root command or group (`error: ... choose another name`, nothing written).
- F2 tool: every staged tool is registered behind `guarded(ctx, <tool>, "module:<tool>")`, so a registrar that forgets it is closed.
- F2 route: a module router is mounted only if every route is an `APIRoute` with a `guard(...)` dependency (`dependency.action`).
- Tests: `tests/services/test_module_name_collisions.py`, `packages/tl-api/tests/test_module_collisions_api.py` (command, path,
  duplicate, unguarded, deny-all walks of installed modules and ext_demo), `packages/tl-mcp/tests/test_module_tool_closure.py`
  (forgotten guard, core clash, module clash, deny-all walks), `packages/tl-cli/tests/test_module_cli_collisions.py` (group clash,
  F3, `tl new module`, template tool and route under deny-all).

Mutation: sentinel P (ignore `reserved` in `_collect_commands`: killed), 4/4 targeted killed (tool name check removed, route path
check removed, CLI group check removed, tool wrapper skipped). The no-guard route refusal is covered by a test but not mutated.

Re-check rulings (F5-F8)
- F5: `_StagedServer` has no real server behind it; `resource`, `prompt` and their `add_` forms raise, so the module is skipped
  whole with the fixed text. F6: `command_index` skips a module whose `command_words` hold a `tl_core` command class name
  (`core_command_names()`, a walk of `Command` subclasses), so a refused module cannot put a word on a core command.
- F7: module routers now mount after `commands.router`, before `web_mount`; core paths are read from the app then. Test uses
  `/projects/{project}/{any}/groups` (the repo has no `/threads/mine`) and shows the core `.../constraints/groups` still answers.
- F8: the tool wrapper is `async def` for coroutine tools and awaits inside `guarded`. Tests: resource refusal, async tool, F6 index.
- Gates re-run: services 70, api 26, mcp 48, cli 39, module-roles 64 passed; `test_commands.py` again in three chunks.
