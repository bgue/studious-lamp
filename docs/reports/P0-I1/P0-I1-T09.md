## Learnings (proposed)
- `SqliteUnitOfWork.ledger` (tl_adapters/sqlite/uow.py) is inferred as `SqliteLedger`. The `UnitOfWork` Protocol declares a mutable `ledger: Ledger`, and pyright treats mutable protocol attributes as invariant, so passing a `SqliteUnitOfWork` where `UnitOfWork` is expected fails pyright (`"ledger" is invariant because it is mutable`). Fix belongs in tl_adapters (annotate `self.ledger: Ledger` in `SqliteUnitOfWork.__init__`), a later ticket. Until then the test file uses a `cast` in `as_uow`. Anyone writing handler tests against the adapter will hit this.
- The ticket's `services/__init__.py` "leave it empty" is inaccurate: the file holds a one-line module docstring. Harmless, but worth correcting in the ticket template.
- `tests/services/` did not exist; no `__init__.py` is needed because pytest runs with `--import-mode=importlib`.
- `uv` prints the `UV_NATIVE_TLS` deprecation warning on every call (already listed in the ticket).
