## Learnings (proposed)
- The pasted `json` keyword parameter shadows `import json`; import the module under another name (here `_json`) or `json.dumps` silently refers to the bool argument. Would have saved time.
- `just check | tail` masks the exit status; use `set -o pipefail` or `${PIPESTATUS[0]}` when recording acceptance exit codes.
- The ticket's pasted docstring lines exceed the 100-column ruff limit; wrap them when pasting, or ruff fails on the first run.
- Baseline `just check` on p0/i1 passes; `tl_schema.generate --check` prints "no generators yet" until T04b or other generators land.

## Open questions / Blocked
1. **Placement vs AGENTS ground rule 5.** AGENTS says SQLite- and Postgres-specific SQL "lives only under `packages/tl-adapters/`". This module is, by design, a table of dialect SQL type names (`JSONB`, `TIMESTAMPTZ`, `BOOLEAN`, ...) placed under `packages/tl-schema/` as the ticket's *Allowed paths* require. I followed the ticket, since it is explicit and the module is codegen-time type mapping feeding generated DDL, not runtime core. The supervisor should confirm that reading before merge, or move the module.
2. **Rule order lets `None` and `json=True` skip the unknown-type check.** Per the ticket's order (rule 1 None, rule 2 json, rule 3 unknown type), `sql_literal("nonsense", None, d)` returns `NULL` and `sql_literal("nonsense", {}, d, json=True)` returns `'{}'` without raising. Implemented as specified; confirm this is intended.
3. **NaN and infinity render as invalid SQL.** The ticket's rule 6 is `repr(float(value))`, which yields `nan` and `inf` for `float('nan')` and `float('inf')`. A Decimal `NaN` in rule 7 gives `NaN` the same way. Not changed here; decide whether T04b should reject non-finite values or this module should raise `ValueError`.
