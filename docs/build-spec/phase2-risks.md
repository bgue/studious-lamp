# Phase 2 — risks and open technical questions, ranked

Status: 2026-10-17, written with `08-phase2-plan.md` v0.2. Scales as `docs/reports/RISKS.md`: likelihood and
impact L, M, H; owner human or agent. The register in `docs/reports/RISKS.md` is updated at the Phase 2 exit; this
file is the input. "Found" cites the Phase 1 evidence; the P1-I3 and P1-I4 surprises were 10 to 40 times, not
percentages: openpyxl at 99 KB of XLSX took 99 s and 7.7 GB (L-P1-I3B-7), `executemany` on Postgres 535 s against
25 s for one bound JSON per chunk (L-P1-I4-11), a per-dimension-bounded XER file 45 s and 649 MB against 3 s with
a total bound (L-P1-I4-13), and the hostile PDF 113 s and 1.3 GB before the byte scan.

## 2. Open technical questions (decided by the orchestrator at wave 0 unless marked owner)

| # | Question | Default if undecided |
|---|---|---|
| T-1 | Is `IwpFacts` read once per evaluation (frozen, hashed) or do checks re-read? | Once; the hash is in the event so a stale evaluation is detectable |
| T-2 | Does a check see other checks' results (constraints_clear after materials_reserved)? | No; the job raises constraints from results after all checks ran |
| T-3 | Are readiness events on the IWP stream (one stream grows by one event per evaluation, bounded by the request de-duplication) or on a readiness stream per IWP? | The IWP stream; a per-IWP cap of evaluations per day from a setting |
| T-4 | How does the awp module learn that a reservation or a tag colour changed without importing those modules? | `ReadinessCheck.watches` names record types; the awp projector listens to any event on those types and queues a re-evaluation for the IWPs linked to the record (bounded by `MAX_RESOLVE_VIA`-style caps on links per record, as ADR-0015 capped links per activity) |
| T-5 | Movement events as `StockLot.Moved` (one event type with `kind`) or eight event types? | One type, `kind` enum; the catalog stays small and the projector is one handler |
| T-6 | Requisition specialisations as `is_a` subclasses (one table each) or one table with a `kind` column and psets? | `is_a` subclasses (typed columns, one workflow definition keyed by record type) |
| T-7 | Where does the first module-to-module import live (`scaffold` → `requisitions.api`, `requisitions` → `materials.api`)? | Allowed for read APIs and the fulfilment call, recorded in the contract; a third consumer triggers an entry-point ADR |
| T-8 | Does the progress export write to `cur_cost_costcode` (earned column of the measure matrix) or only to a file? | File only; the mirror stays the cost system's (ADR-0015 §1); a later connector writes back |
| T-9 | Period for the weekly plan: ISO week from the project calendar or the schedule's data date? | ISO week in the project time zone; the look-ahead window starts at the published snapshot's data date |
| T-10 | Do we need a shared `tl worker` now? | No; filed as a follow-up with `ModuleSpec.job_kinds` |
| T-11 | QR deep links (brief §19.1) need a base URL; which setting? | `api.public_base_url` (new platform key; `n_a` in the pack when unset) |
| T-12 (owner) | Which of brief §17 items Phase 2 touches: R1 (rebuild time, more projectors), R2 (pset queries on scope items), R5 (workflow configurability: five new workflows with company defaults), R7 (feed noise), R14 (simulated data realism: COAA rates), Q7 (gap-free numbering for requisitions and IWPs), Q16, Q17 | R1, R2, R7 measured in the I2 and I5 benches; R5 limited by "company defaults, no project overrides in Phase 2"; Q7 interim D8 stays (allocation inside the transaction); Q16 and Q17 are P2-Q1 and P2-Q13 |
