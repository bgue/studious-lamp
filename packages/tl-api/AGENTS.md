# AGENTS.md — tl-api

Read the root `AGENTS.md` first. These rules add to it.

- No business logic here. Routes call `tl_core` services or handlers through `ctx.backend(readonly)`; no SQL, no ledger access, no adapter imports outside `backend.py`.
- Every route depends on `guard("<action>")` (it authenticates and calls `authorize`). A route without it fails `test_every_route_calls_the_hook`. Never design roles or permissions here: that is a human gate (ADR-0005).
- Open the unit of work inside the handler, never in a `yield` dependency (the response must not be built before the commit).
- Every expected failure comes from `tl_api/errors.py`. A new `ServiceError` subclass needs a row there; do not add an `Exception` catch-all handler (it breaks keep-alive connections).
- A command body never carries `actor`. Do not add a way to set it from a request.
- `docs/reference/openapi.json` is generated and drift-checked by `just check`: change a route, run `uv run python -m tl_api.openapi`, commit both. A ticket that only implements a route body must not change any signature, decorator or description.
- Any response that returns file bytes keeps `attachment`, `nosniff` and `application/octet-stream`.
- The client (`tl_api/client/`) keeps the `ClientInterface` method names and parameters; `tests/api/test_client_roundtrip.py` compares it with the embedded client. Put every id in a path through `quote()`.
- Settings routes (`routes/settings.py`) are thin: one `tl_core.settings` call each, a write answers with `view_at` (the key as seen at the layer it changed), the actor is the token's and the source is `api`. Every write route uses `guard("setting.write", changes_records=True)`; a new one must too. Revert undoes only the latest change at a layer.
- Modules that build endpoints in a loop (`commands.py`) must not use `from __future__ import annotations`.
- SSE tests need a real server (`Harness.live()`); the in-process test client buffers whole responses.
- The proposal routes decide for the token's actor and never take an `actor` from a body. Do not add a route that proposes (agents propose through MCP) or one that lets an agent decide; both are the permission model, a human gate. A failed accept stays a 200 with `status: failed`.
- `guard(action, changes_records=True)` marks a route that changes a record: an `agent:` token is refused there with 403 `agent_must_propose` (B15). A new command route is covered unless its name is in `AGENT_DIRECT_COMMANDS` (the four feed commands); a new write route outside `/commands` must pass `changes_records=True`. `test_an_agent_token_cannot_run_any_record_changing_command` iterates the command table.
- The body routes (`routes/extypes.py`) are thin: `PUT /records/{id}/body` calls `bodies.store_record_body`, the same function the embedded TUI client calls; do not add a second write path. Reads go through `bodies.read_body` outside the unit of work so a quarantine is recorded. A route docstring is OpenAPI text: no implementation notes. Both writes are `changes_records` routes.
- Identity (P1-I0, ADR-0009): `guard(action)` resolves the principal and runs the role `Authorizer`; a new route needs an action name, and `test_every_route_action_is_decided_for_agents` fails until it is in `AGENT_ACTIONS` (agents may) or the test's denied set. `/admin/*` routes are all `admin.*`; hash outside write transactions (`prepare_password` before `ctx.backend()`); never log, echo or put a password or token in an error, `repr` or event. `/auth/sign-in` is the one open route besides `/health`; the body limit (16 KiB `/auth`, 64 KiB `/admin`) and the source limiter run before authentication. Change an error row only with `tl_api/errors.py` and its test.
- The ledger is a `DbTarget` (`ApiSettings.db_path`, `--db`, `TL_DB`): a SQLite path or a `postgresql://` URL. `tl_api.backend.open_backend` opens either; check for a ledger with `tl_adapters.backend.ledger_exists`, print it with `display_target`, and never import `tl_adapters.sqlite`. A bad target or an unreachable server is `error: ...` and exit 2 before the server listens; never echo the value.
- A route that takes a command body builds the body model with `request_model` (it refuses the reserved `source`, `correlation_id` and `causation_id` of a publication, ADR-0014). Do not write a body model for a command by hand: `test_api_reserved_identifiers.py` walks the published API and fails for a route with a `source` field that does not use it.
