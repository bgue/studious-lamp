# AGENTS.md — tl-extract

Read the root `AGENTS.md` first. These rules add to it. Everything here reads **untrusted bytes**.

- An extractor is pure: no ledger, no unit of work, no network, no clock, no randomness, no file path taken from the source. The only input is the stream and `SourceFile`; the same bytes and options give the same result (`tests/contract/test_extractor_contract.py`).
- `extract` never raises. Wrap the body in `reading.run_guarded`: a `Refusal` or any other exception becomes a `failed` result. Messages hold fixed text and, at most, a cleaned short excerpt of the file (`reading.shown`). Never `str(exc)`, never a path, never a stack trace.
- Refuse, never truncate (D4): more than `MAX_SOURCE_BYTES`, `MAX_ROWS`, `MAX_COLUMNS`, `MAX_CELL_CHARS` or `MAX_CELLS` (the contract's: 1 000 000 data cells, so 20 000 x 50 fits and 20 000 x 200 does not) is a `failed` result. The package adds `MAX_TOTAL_CHARS`, `MAX_BLANK_RUN` (data after that many blank rows is refused, trailing blank rows are harmless) and `MAX_PROBLEMS`. The job runner's subprocess limits (FANOUT D9: wall clock, CPU, address space) are the backstop, not the plan: every reader bounds its own cost, and a reader that streams counts as it goes and refuses at once. Do not raise a limit without a test and a note in the report.
- A cell with a control character (other than tab, CR, LF) or a lone surrogate is left empty and is a problem of its row, as in the P1-I2 import: a NUL crashes Postgres and a surrogate poisons the driver connection (L-P1-I2-17, L-P1-I0A-14). Metadata text goes through `reading.clean_metadata_text`.
- XLSX: no workbook library (openpyxl builds a whole row or the whole shared-strings table before a cap can look at it). The parts are streamed with `xml.etree.ElementTree.iterparse` (`xlsxxml.py`) and elements, depth, strings, cells and characters are counted as they come. Never evaluate a formula (read the stored `<v>`), never open an external link, only read parts that were scanned for a document type or entity (`xlsxgrid.scan_xml_parts`) and end in `.xml`. Check the end-of-central-directory record and the declared sizes before `zipfile` builds anything. A new reader of a ZIP-based format needs the same steps and the same kind of tests as the XLSX reader's (`test_xlsx_hostile.py`).
- PDF: pypdf is not a bounded reader (a page count asked of `len(reader.pages)` once cost 113 s and 1.3 GB on a file of 1.2 MB). Only the information dictionary and `/Root/Pages/Count` are read. Keep every step of `pdfinfo.py`: the byte scan before pypdf (`check_pdf_bytes`: object streams, cross-reference sections in any `#xx` spelling, `/Length`, `/Size`), pypdf reading through `_BudgetStream` (every operation it makes on the file is counted, so a 47 MB title, a huge `/Kids` array or a long `/Prev` chain ends in `pdf_too_complex`; the exception is a `BaseException` so that pypdf's own `except Exception` cannot swallow it), `strict=True`, the 2 MiB decompression limits (`apply_configuration`), no page tree walked, pypdf's log records dropped. Never scan a file with a regular expression that has a group or an alternation under a repeat: Python keeps state per character (a 47 MB string reached 5.3 GB). An encrypted PDF is refused without a password attempt. Do not add pdfplumber, Camelot or a text extractor here: ADR-0008 decision 8 keeps content extraction stubbed.
- Images: only the header is read, by hand. There is no decoder, so an image costs nothing to "open". Do not add Pillow or an OCR engine to read pixels without a pixel limit, a test of a decompression bomb and an ADR.
- A row problem's `row` is the place of the row among the kept data rows (the first is 1), so it indexes `rows`; blank rows are skipped and counted in a note.
- Text that starts with `=`, `+`, `-` or `@` is returned as it is. Anything that writes it back into a spreadsheet or CSV for a person must escape it; extractors do not.
- Options are checked strictly (`options.TableOptions`, unknown keys refused). Add an option by adding a field, a test and a line in the README.
- Never name a module `types.py` (L-P0-I5-B1). Test helper modules have unique names (`extractsupport.py`); tests build every file in memory (`extractsupport`), they do not read fixture files except the golden dataset and the document schemas.
- Every extractor's tests call `check_extractor_contract` and cover: an oversize file, too many rows and columns, a long cell, malformed input, and determinism.
