# AGENTS.md — tl-core

Read the root `AGENTS.md` first. These rules add to it.

- Dialect neutral: depend only on the Protocols (`Ledger`, `UnitOfWork`, `Bus`, `Projector`). SQL here uses SQLAlchemy `text()` with bound parameters and no dialect features.
- Projectors are deterministic: no clock, no generated ids, no outside calls. They never delete rows of history; `reset` clears only their own tables.
- Business rules live in `services/`. Clients (CLI, TUI, API, MCP) call handlers and queries and add none.
- Never write `cur_*`, `hist_*`, or `v_*` DDL here; load it from `tl_schema.ddl_loader`.
- Publish order equals commit order. Never publish while holding a lock a subscriber could need; use `OrderedPublisher`.
- Test-only helpers (`projection/testing.py`) are never registered by default.
- pyright strict applies to `src/`. No ignores.
- Pset events: `Pset.ValuesSet` payload is `pset, layer, values, effective_schema_hash, conformance, units`; the projector reads only the payload and the rows already in the database, never the schema provider. A `None` value in `values` is a ledgered clear.
- Services get the effective schema from `tl_core.schema_provider.get_provider()`; tests install a provider with `use_provider`.
- `services/psets.py` signatures (`SetPsetValues`, `handle_set_pset_values`, `form_metadata`, `conformance`) are a contract with the TUI; change them only through an orchestrator decision.
- Files: `files/types.py` is frozen (change only through an orchestrator decision). Never trust client-declared size or hash; verification happens in the store's `put` and in `FileService`. Dedupe without bytes only against an `available` file in the same scope. A quarantined file is readable only by its uploader. Supersession happens at `File.Processed`.
- File events live on a `core.File` stream (stream id = file id). Quarantine rules are in `files/lifecycle.py` alone; handlers and the projector both call it.
- Anything that serves file bytes (API) must send `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`; `content_type` is client-declared.
- Query language: SQL is built only from the allow-lists in `query/fields.py` and bound parameters; never splice caller text, a column name or an operator into SQL. Every compiled predicate must be two-valued (`col IS NOT NULL AND col = :v`), or `NOT` and `!=` silently drop rows with no value. A new envelope column is added to `ENVELOPE_FIELDS` (and the parser, compiler and reference page follow); a new AST node is an orchestrator decision.
- The parser raises only `QuerySyntaxError`, with a 0-based `position`; bound input length, nesting and node count. Property tests (`tests/query/test_query_properties.py`) must stay green.
- Change feed (`changefeed/`): delivery must follow commit (`seq`) order per subscriber and drop repeats by `seq`, because the bus and the poller feed one registry. Callbacks run under the registry lock: never block in one; use `subscribe_queue` for a consumer on another thread. Do not call this package `feed`: `Feed.*` events are the activity feed (P0-I6).
- Links: a link is its own stream (`core.Link`, stream id = link id, scope = the from-record's scope; the target is in that scope or `company`). Status changes go through `links.lifecycle.next_status` only; there is no broken-to-active route. Never add a delete.
- Numbering: allocate a key inside the transaction that creates the record (`allocate_key`), never before it; the counter stream's expected-version check is the second line of defence. `Pattern.parse` accepts only the canonical spelling of a sequence.
- Workflow: guards are evaluated against the target state; a guard failure raises `GuardFailedError` carrying every `GuardResult`. `expected_version` is checked after the state and guard checks. The roles list is caller-supplied (D12); never read roles from the database until auth exists.
- A new command that needs several writes to be atomic composes the existing handlers in one unit of work (see `services/edit.py`, L-P0-I3-10); do not add a second write path.
- Definitions (workflows, expected links, numbering patterns) are files under the schema directory; `schema/**` changes are human-gated.
- Webhooks (`tl_core.webhooks`): a secret is never logged, put in an event, an error message or a `repr` (`SigningSecret` hides it). The outbox projector is registered last and reads other projections' rows; a delivery body is built once and re-sent unchanged; ordering, signing and egress changes need orchestrator or human review. Read a stream's version inside the transaction (`subscriptions.current_version`), not through `uow.ledger`.
- A new event type needs a class in `schema/core/events.yaml` in the same change (a test fails otherwise); run `just gen`.
- Settings (`settings/`): every reader goes through `value_of(conn, key, ...)` in the caller's transaction or a `SettingsReader` passed in; there is no global reader, and no code keeps a setting in a module constant. Event streams are `setting:<layer>:<key>` (type `core.Setting`); the ledger is the only record of a change, and `setting_effect_applied` is the one operational table (not rebuilt from events). A new key is data in `schema/settings/platform.yaml` (a schema change: `just gen`). A key with an item rule goes in `settings/checks.py` (`ITEM_CHECKS`). The service refuses; a surface never re-checks. Values are copied on the way out. Anything hostile in a value (4,300-digit integers, deep nesting) must become a `SettingError`, not another exception type.
- Feed (`feed/`, `projection/feed.py`, `services/feed*.py`): only a post's author edits or retracts it (`require_author`, `NotPostAuthorError`); reactions are open. `feed/types.py` is frozen. Card rules are in `feed/cards.py` alone and use only event fields, never the clock; the projector reads only its own tables so a feed-only rebuild equals a full one. A post is not a record: only the link service's `from` end accepts one. A hashtag never changes a record; the only write beyond the post is a *suggested* link, and `SuggestLink` refusals (duplicate, declined, voided) are skipped, not raised. `Feed.*` event types need catalog classes (`schema/core/feed.yaml`).
- Proposals (`proposals/types.py` frozen, `services/proposals.py`, `projection/proposals.py`): a proposal never changes a record; only `accept_proposal` runs the stored command, as a `user:<id>`, with `source=mcp:<agent>` and the `Proposal.Created` event as cause. `precheck` must end in a rollback (the unit of work exits with an exception) and `accept_or_fail` must record `Proposal.Failed` in a fresh unit of work, never inside the one that rolled back. A proposal carries no workflow roles. `Proposal.*` events need catalog classes (`schema/core/proposals.yaml`) and stay transparent to feed cards. Who may decide beyond "a person" is the permission model: a human gate.
- Archive (`tl_core.archive`): `archive/types.py` is frozen. A segment's files are written ndjson, parquet, manifest, and the manifest is the commit marker; never write a manifest first and never delete or rewrite a segment file. Sealing and verifying use portable SQL only; restore does not belong here (it needs `tl_adapters.<dialect>.admin.restore_events`). Do not name a module `types.py` elsewhere and do not run scripts from `archive/`: the standard-library `types` clash (L-P0-I7-A3). `import duckdb` stays inside the functions that use it. Signing keys never go in the repository or in a log.
- A webhook subscription with no usable signing secret (a restored database has none) is never sent to and never dead-lettered: `DeliveryEngine.claim` skips its deliveries and leaves them pending, logs once per subscription per cycle (never the secret id), and listings show `status_label` `needs_secret`. Do not make the engine send unsigned or turn a missing secret into a retry or a dead letter.
- Performance (P0-I8 D13): a query rewrite or a projector change must give the same results (dangling links, empty and NULL values included) and the same rows; the plan tests (`tests/query/test_query_plans.py`) and the statement budgets (`test_*_projector_statements.py`) pin what the speed depends on. Pset and link predicates that must hold compile to `id IN (set)`; negations stay correlated `NOT EXISTS`. A projector costs round trips on Postgres (about 0.5 ms a statement): count statements before adding one.
- Extension types (`extypes/`): a registered version is immutable: changed files are a `conflict` event, never a new registration, and the projection keeps the registration. `validate_package` never raises and is the only reader of package files at sync time; imports in a package are confined to `linkml:types`, the core extension schema and plain-named files of the package (L-P0-I8B-1). A body is validated before anything is put or appended, stored under its own hash, and read only through `read_body` (callers with a unit-of-work factory) so a mismatch is quarantined outside the failing transaction; `tl_body_quarantine` is operational and a rebuild never clears it. Direct writes to an object-backed type's index pset are refused (`BodyNotAllowedError`); the index fields follow the body. Status is judged from the registry row before any file is read (`refuse_inactive`). A new `ServiceError` here needs a row in `packages/tl-api/src/tl_api/errors.py`. Docstrings of anything that reaches OpenAPI, CLI help or an MCP description are for the reader, not implementation notes (L-P0-I8B-6).
- Extension type settings (`extypes/settings_link.py`): the settings registry is process-wide, so a test that registers a type's keys leaves them behind; the root `conftest.py` calls `settings_link.forget_all()` after every test. Registration reads `settings.yaml` only from files whose hash still matches the registration (`TypeLoader.verify`), never from a quarantined or edited package. A refresh must not raise into the schema read.
- `tl_core.auth` is credential code (ADR-0009). `types.py` is frozen: change it only by orchestrator decision. Hash before a write transaction (`prepare_password`), never inside one; never log, repr, store in an event or put in an exception text a password, a hash or a token (`Principal`, `AccountView`, `AgentTokenView` carry none). Validate every id, name and event name that reaches a query (`names.is_id`, `check_username`, the audit event list): a NUL or lone surrogate breaks a pooled Postgres connection. New agent powers are added to `AGENT_ACTIONS` (or the MCP list) on purpose; the default is closed. Account events must stay out of the feed, webhooks and default subscriptions, and are redacted in the lake.
- Modules (`modules.py`, ADR-0010): the core never imports a module; it asks `ModuleSpec` hooks. A module record is a row of `cur_core_record` and a row of the module's own table, so a module projector must move the envelope row's `version`, `last_seq` and `updated_at` on every event it handles. A module that is installed and does not load is a `ModuleLoadError`, never a silent skip. `CreateRecord` keeps refusing module types; the module's own command calls `create_module_record`.
- A module record type allows no generic command (`UpdateRecord`, `VoidRecord`, `SetPsetValues`, `TransitionWorkflow`, `AddLink`, `SuggestLink`, `AttachFile`) unless its `ModuleSpec.generic_commands` lists it; a handler that loads a record by id and changes it calls `require_generic_command(record.type, "<CommandName>")` first (ADR-0010 addendum).
- A record's class may bind psets (`bound_psets`): pass the names to `validate_psets`, `evaluate` and `form_metadata`; never widen a pset's `applies_to` for it.
- Untrusted work (`derivation/envelope.py`, FANOUT D9 and D10): an extractor, and the application of a document schema to cells, run only through `run_in_envelope` (a fresh interpreter, a scrubbed environment, `RLIMIT_AS` and `RLIMIT_CPU` that must be settable, a wall clock, `python -P` so the worker's current directory is not on the child's path, `SIGKILL` of the group so a process the extractor started does not outlive the call). Nothing that comes back from the child is ever unpickled (`pickle`, `multiprocessing` connections' `recv`, `eval`): the child answers JSON bytes that the parent reads with a length cap and parses with pydantic. Never put a secret, a path or a connection in the child's header or environment. Rlimits do not confine the filesystem or the network: do not describe the envelope as a sandbox. A breach is a fixed problem with fixed text (`extraction_limit`, `validation_limit`); never copy exception text or a trace from the child into a message. `contract_problem` must bound every part of a result that can reach an event or a report.
- Identifiers only the server sets (`services/reserved.py`): a correlation id or causation id starting `derive:` and a source starting `import:derived-` or `compensation:` are refused on a client command (the body model that `tl_api.commands.request_model` builds, which every route taking a command body uses, and proposals call `refuse_reserved`/`refuse_reserved_fields`; a new route builds its body with `request_model` and a test walks the published API). Compensation reverses ids a publication recorded, never "events with this correlation id".
